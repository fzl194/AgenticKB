## 1. 服务自述（MCP Server Instructions）

握手响应中服务端注入的 `instructions` 原文要求 Agent 这样用它：

1. **domain 必须显式指定**，不得猜、不得用隐式默认域；不确定就先问调用者。
2. **检索范围由密钥主人的开放库决定**：只开放一个库时连 `kb_names` 都不用传；多库时可用 `kb_names` 收窄。
3. **渐进式工作流**（核心设计）：
   `search_knowledge 模糊找` → `inspect_knowledge 看 ref 的真实能力` → `navigate_structure 结构导航 / query_structured_asset 表格精确查询 / get_document 读整文` → `get_evidence 取截断证据的完整原文`。
4. **错误自修正**：错误带稳定 code（unknown_field / out_of_scope / expired_ref…），按提示改参数重试。
5. **回答纪律**：区分"证据直接支持 / 基于证据的推断 / 缺失不确定"，不得编造命令、参数、约束、依赖、步骤。

> 评价：instructions 写得相当好——把"先 inspect 再下钻""不猜 domain""错误重试"这些用法约束讲清楚了，对 Agent 消费方友好。**但它没有告诉调用者合法的 domain 取值有哪些**，而这是硬门槛（见缺陷 D1）。

## 4. 工具逐项测试

### 4.1 list_knowledge_bases —— 列出密钥开放的库 ✅
- **用途**: 无参调用，列出当前密钥可检索的知识库，是一切检索的起点。
- **实测**: 返回 `test333`（未绑定范式）、`test222`（绑定 `system-lexical-retrieval` 词法范式）。
- **备注**: 返回含 `default_paradigm_id` 字段，工具描述只写了 `{id,name,description}`——轻微文档漂移（D6）。

### 4.2 list_documents —— 列库内文件 ✅
- **用途**: 按库名列文件清单（名称/状态/大小/修改时间），`limit`/`offset` 分页。
- **实测**: test333 返回 5 个 `uploaded` 状态文件；test222 返回 3 个 `mined` + 1 个 `failed`；分页 `limit=3` 生效。
- **错误路径**: ✅ 未知库 → "知识库 'no_such_kb' 未开放或不存在。当前开放：test222、test333。"（友好，不泄露库是否存在）。
- **环境观察**: test222 的《实现原理.md》状态 `failed`（挖掘失败，平台侧待处理）。

### 4.3 search_knowledge —— 核心检索 ⚠️（通路 OK，错误面和召回有硬伤）
- **用途**: 按 `domain`（必填）+ `query` 模糊检索，返回**纯证据面** `query/evidence/has_more`（无 score、无内部 id——设计上防止 Agent 拿内部标识当权威）。
- **实测（命中路径）**: `domain=cloud_core_network, query="系统间改变"` → 7 条证据，覆盖 4 种类型（prose/list/document/table），每条带 `ev_` ref、`st_` structure_ref、`doc_` document_ref、来源（库名/文件名/章节）、`truncated` 标记。两种证据被截断（truncated=true）——正好喂给 get_evidence。
- **参数实测**:
  - `kb_names=["test222"]` 收窄 ✅；不传 = 搜全部开放库 ✅（结果一致）
  - `top_k=2` ✅ 精确截断 2 条
  - `within={"structure_ref": …}`（不支持键）→ ✅ **显式** HTTP 400 `unsupported_scope_filter`，并给出支持键清单 `document_refs/section_refs/evidence_types/asset_types`——"不支持显式报错不静默忽略"的契约兑现
- **错误路径**:
  - `kb_names=["nope"]` → ✅ 友好报错带开放清单
  - **domain 传错（generic/civil_engineering/odn）→ ❌ HTTP 500 裸 `operator_error: scope_resolve kb_not_found`**（D2）
- **召回行为（重要）**: 词法范式下**加词杀召回**——`"系统间改变"` 命中 7 条，`"系统间改变 如何激活"` 和 `"如何激活"` 均返回 0 条（serving.log 确认 `output=0 evidence`，非异常）。Agent 用自然语言提问很容易扑空（D3）。

### 4.4 get_evidence —— 取证据完整原文 ❌（全挂，确定性 bug）
- **用途**: search 结果 `truncated=true` 时，把 `ev_` ref 传回取完整原文；可选 `mode` 控制展开粒度（auto/exact/window/parent/whole_document）。
- **实测**: 对截断的 document 型证据（默认 mode 和 whole_document）及未截断的 prose 证据，**一律 HTTP 500 `internal_error`**。
- **根因（serving.log 已定位）**: `InternalStructureController.evidence`（Java :8081）SQL 错误——
  ```sql
  SELECT u.snapshot_id, u.canonical_evidence_id AS ref
  FROM ( SELECT DISTINCT r.snapshot_id, r.canonical_evidence_id
         FROM asset_retrieval_units_v2 r WHERE r.snapshot_id IN (…) ) u
  ORDER BY u.snapshot_id ASC, u.ref ASC   -- ❌ u 里没有 ref 列
  ```
  `ref` 别名定义在外层 SELECT，子查询 `u` 只有 `snapshot_id/canonical_evidence_id`，PostgreSQL 报 `column u.ref does not exist`。
- **修复建议**: ORDER BY 改为 `u.canonical_evidence_id ASC`，或在子查询内起别名。**该工具在修复前完全不可用**。

### 4.5 inspect_knowledge —— 看 ref 背后的能力 ✅（设计亮点）
- **用途**: 对任意 ref（ev_/st_/doc_）查询：能否导航、能否结构化查询、可聚合性、表格资产清单（列名/类型/可用操作）。"下钻前先 inspect"是官方工作流。
- **实测**: 对表格证据 `st_d8MH2r7-gnA7` 返回——
  - capabilities: `can_read_document/can_navigate/can_query_structured=true`, `can_aggregate=false`
  - relations: `parent/ancestors/container/caption`
  - assets: 表格 1 行 × 3 列（涉及NF/支持版本/功能说明），每列 ops `eq/ne/in/contains/is_null/count`
- **错误路径**: ✅ 拼造 `doc_<内部id>` → `[invalid_ref] ref 格式非法`（ref 是不透明编码，无法伪造——安全设计 OK）。

### 4.6 navigate_structure —— 结构导航 ✅
- **用途**: `st_` ref 沿白名单关系（parent/children/previous/next/ancestors/descendants/container/caption/footnotes/references）取相邻节点，返回可继续导航的 `st_` ref。
- **实测**: `parent` → 拿到"可获得性"章节节点 ✅；`children` → 返回 segment/table/table_row 混合子节点（带 ordinal/block_type）✅。
- **错误路径**: ✅ `relation="siblings"` → `[unsupported_operation] 未知关系…允许：[ancestors, descendants, …]`（列全白名单）。

### 4.7 query_structured_asset —— 表格精确查询 ✅
- **用途**: 对表格资产做 schema-bound 查询（select/where/order_by/limit，聚合 aggregate）。字段名/操作以 inspect 返回为准，**不是模糊搜索**。
- **实测**: `select=[涉及NF,支持版本] + where(涉及NF eq SGSN)` → 精确命中该行，返回真实表名与行数据 ✅。
- **错误路径**: ✅ 查不存在字段 → `[unknown_field] 未知字段…可用字段：涉及NF、支持版本、功能说明`。**错误提示闭环可用：按提示改参数即可恢复**。

### 4.8 get_document —— 按文档读全文 ✅
- **用途**: `doc_` ref 读整个文件的章节 outline + 切片分页（默认 100 段/页，cursor 翻页）。
- **实测**: 返回 10 节 outline + 首页 2 段（`limit=2`），`total_segments=15`、`has_more=true`、`cursor="bzoy"`；**cursor 回传翻页成功**（拿到第 3、4 段，新 cursor）✅。

### 4.9 upload_document —— 上传文件 ✅
- **用途**: base64 文件（≤50MB）上传到开放库；**不自动挖掘**，需密钥主人在平台界面发起挖掘后才可检索。
- **实测**: 上传 162B 测试 md 到 test333 → 返回 `document_id` + 明确提示"已上传（未自动挖掘）"；`list_documents` 复核确认落库（status=uploaded）✅。
- **错误路径**: 源码含 base64 合法性校验（非法编码 → 友好 ToolError），本次未实测。
- **遗留**: 测试文件 `mcp-upload-test.md` 留在 test333，可在平台删除；未发起挖掘。

## 5. 缺陷与风险清单

| 编号 | 级别 | 问题 | 影响 | 建议 |
|---|---|---|---|---|
| **D1** | **P0** | **合法 domain 无任何发现途径**：instructions/工具面都没有列出可用域；传错域即失败 | Agent 无法自主正确使用（本次是靠读服务端 `domain_registry.yaml` 才找到 `cloud_core_network`） | instructions 或 list_knowledge_bases 返回中带上库所属 domain；或新增 list_domains |
| **D2** | **P0** | **错域检索以 HTTP 500 裸泡**（`operator_error: scope_resolve kb_not_found`），不是 ToolError 稳定 code | 违背"错误带稳定 code 可自修正"的自述契约；严格客户端可能断链 | serving 侧把 kb_not_found 归一为结构化 ToolError；顺带缺 domain 场景给"域下无库/域不存在"区分提示 |
| **D3** | **P0** | **get_evidence 全量 500**：SQL `ORDER BY u.ref` 引用不存在的列 | 截断证据取不回原文，渐进式工作流断在最后一环 | 改 `ORDER BY u.snapshot_id, u.canonical_evidence_id`（见 §4.4） |
| **D4** | P1 | **词法范式加词杀召回**："系统间改变"7 条 → "系统间改变 如何激活" 0 条 | 自然语言提问（Agent 主要形态）大量扑空 | 范式侧改 OR/加权混合召回，或接语义向量范式兜底 |
| **D5** | P2 | 匿名 initialize 放行，泄露 serverInfo/instructions | 元数据泄露（工具面已被空清单挡住，实际风险低） | 网关层对无钥请求 401；源码注释已知 fastmcp 3.4.7 限制 |
| **D6** | P2 | list_knowledge_bases 实际返回 `default_paradigm_id`，工具描述未写 | 轻微文档漂移 | 更新工具描述 |
| **D7** | P2 | test222《实现原理.md》挖掘 failed | 库内容缺失（环境问题非工具面） | 平台侧重挖 |

**错误处理一致性总评**：identity 层（无钥/错钥/未开放库）与参数校验层（unknown_field/unsupported_operation/invalid_ref）的 ToolError 契约兑现良好、提示可操作；**但检索管线深处的错误（scope_resolve/unsupported_scope_filter/get_evidence）都以原始 HTTP 400/500 JSON 泡出**，两类错误形态不统一。

## 6. 协议层观察

- **传输**: streamable-HTTP（POST /mcp，响应 SSE `text/event-stream`，`mcp-session-id` 头维持会话），协议版本 `2025-03-26`。
- **结构化输出**: 每个工具都声明 `outputSchema`，命中路径同时返回 `structuredContent`（Claude Code 客户端正确消费）。
- **会话**: session id 稳定，跨多次调用有效；错误后 session 不失效（复验通过）。
- **Claude Code 接入**: 项目根 `.mcp.json`（http + Bearer header）即接即用，工具面挂载后原生调用正常。
