## 1. 前置条件（重要）

1. **批次1 必须先完成部署**：apply + 三服务重启 + `backfill_user_domains.py`
   迁移三连全部结束。本批的 `mcp-key-verify` 验钥联动（can_create_in_domain /
   钥匙域绑定校验）依赖 `user_domains` 表已有数据，批次1 未迁移则所有钥匙
   校验都会因零绑定而拒绝。
2. **后端与前端必须同批发布**：旧的 `/users/me/mcp-access` 路由已删、旧
   `mcp_access_service` 已退役。单独出后端包（不带新 dist）会让 UI 上的
   钥匙管理页立即 404。deploy-sync pack 时确认 `kb-ui-dist/` 为新构建产物。

  部署公告可提醒：重启窗口期内上传失败的 Agent 重试即可。

## 4. 验收 checklist（51号 spec §5.6 五项）

### 4.1 创建钥匙必须选域，开放库只能勾该域

- [ ] UI「MCP 钥匙」页新建钥匙：**必须选择一个绑定域**才能提交；
- [ ] 开放库勾选清单**只列该域的库**；构造越域勾选（抓包改 payload）
  保存后重新打开：**越域勾选被服务端强校验丢弃、自动消失**，不报错不落库。

### 4.2 存量 Agent 无感/有报告

- [ ] 原**单域**钥匙的 Agent：迁移后旧钥匙（明文不变，按哈希命中）调用
  全部正常，**完全无感**；
- [ ] 原**跨域**钥匙的 Agent：收到（admin 转发）含**被丢弃勾选清单**的
  迁移报告；其主域行为不变，被丢弃域的库需另建新钥匙。

### 4.3 域解绑即时阻断

- [ ] admin 在用户管理页解绑某用户的一个域后，用该用户**绑定该域的钥匙**
  立即调用任一 MCP 工具：返回**人话错误**
  「该钥匙绑定的知识域已被解绑，请联系管理员或换用其他钥匙」（403），
  不是裸 500 / 不是静默空结果。

### 4.4 票据绑钥匙，吊销即失效

- [ ] 用钥匙 A 申请上传票据 → admin 吊销（删除）钥匙 A → 用原票据调
  `upload-direct`：**404**（票据 peek 先验钥匙活性，票已白吃）。

### 4.5 双钥匙域隔离

- [ ] 同一用户建两把不同域的钥匙 A（域1）、B（域2）；
- [ ] A 检索/kb_tree：只见域1 的库；B 只见域2 的库；**互不可见**；
- [ ] A 指定访问域2 的库 ID：被拒绝（域不匹配人话错误）。

## 5. 回滚预案（51号 §7.2 批次2 裁定）

1. **代码回退 + 重启 mining/mcp_server 即可**：旧 `mcp_access` 表与数据
   **未动**（迁移只读不写不删），旧代码回退后按旧表继续工作；
   `mcp_keys` / `mcp_key_open_kbs` 两表留存无副作用，无需 drop。
2. **放量前必须完成回滚演练**：spec 7.2 裁定——
   - 迁移后**尚未有人建新钥匙**＝干净回滚窗口（推荐在此窗口内演练）；
   - 已有人建新钥匙后回滚＝新钥匙丢失，**可接受**（用户重建即可），
     但需在公告中说明。
3. 回滚时前端 dist 一并回退（同批发布原则对称适用）。
