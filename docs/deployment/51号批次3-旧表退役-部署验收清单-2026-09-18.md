## 3. 删表（mining 重启完成后）

**唯一入口＝本脚本**（reset 工具的重置清单已不覆盖旧三表，不能替代本脚本）：

```bash
# 连接参数走环境变量 PG_HOST/PG_PORT/PG_DBNAME/PG_USER/PG_PASSWORD

# 1) 干跑，人工复核
python drop_legacy_mcp_tables.py --dry-run
# 重点看：
#   - 三表（mcp_access / mcp_open_kbs 及关联）行数是否符合预期
#   - 门禁判定：各条门禁是否全部放行（含门禁 a＝新钥匙体系就绪、
#     门禁 b＝计数比对 keys ≥ access）

# 2) 实删（mcp_open_kbs → mcp_access 顺序，显式 RESTRICT，单事务）
python drop_legacy_mcp_tables.py --yes

# 3) 复跑确认已退役
python drop_legacy_mcp_tables.py --yes
# 期望：报告「已退役/不存在」，退出码 0
```

**退出码约定**：

| 退出码 | 含义 |
|---|---|
| 0 | 完成，或无事可做（表已退役） |
| 1 | 门禁拒绝或执行出错——必须排查后重跑 |

**门禁 b 被拦截时**：先跑 `backfill_mcp_keys.py --dry-run` 复核迁移
状态；确认存量已全部迁移、确需强制删除时才用 `--force`。

> ⚠️ **`--force` 为高危操作**：仅在人工确认门禁误报/业务显式接受
> 丢弃未迁移数据时使用，使用前留存 dry-run 报告备查。

## 5. 回滚说明（spec §7.2 批次3 裁定）

1. **删表执行后回滚窗口即关闭**：若必须回退到批次2 之前的状态，
   `mcp_access` / `mcp_open_kbs` 中的**旧钥匙数据不可恢复**——用户需
   在旧代码下重建钥匙。此为 spec §7.2 显式可接受项，回退公告中需说明。

   pg_schema 注册；回退后重启 mining，启动时按注册清单重放重建
   **空表**（结构在、历史数据无）。
