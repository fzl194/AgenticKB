# 06 · P07 Run 执行模型：S1 启动自愈交付件

> 日期：2026-08-25
> 分支：`codex/fix-p07-run-startup-recovery`
> 范围：P07-S1；不包含租约、多实例认领或独立 Worker。

## 交付结果

- Mining API 启动后按所有启用 domain 分库扫描遗留的 `queued/running` Run；仅处理 `finished_at IS NULL` 的记录。
- 每个命中的 Run 以单条 `UPDATE ... RETURNING` 原子标为 `interrupted`，写入 `interrupted_by=restart` 元数据，避免先扫描再更新的竞态。
- 仅 `execution_engine=workflow` 的 Run 自动恢复；legacy Run 只标记中断，保留人工处置，避免错误调用其不支持的 resume 语义。
- 恢复任务全局限并发为 2；单个 domain 扫描或单个恢复失败会记录日志，不阻断其他 domain 或 API 启动。
- `/api/runs/{run_id}/resume` 的 daemon 线程异常现在会将已经进入 `running` 的 Run 标为 `failed`；线程启动失败会释放域锁并返回 500。

## 验证

- 新增 `test_mining_startup_recovery.py`：覆盖 workflow/legacy 分流、原子更新字段与单 domain 失败不中断全局扫描。
- 运行 `test_mining_startup_recovery.py` 与 `test_mining_run_submission.py`：35 项通过。

## 运行边界

- S1 仅适用于当前单 Mining API 实例部署。多实例前必须实施 P07-S2 的数据库租约与跨实例域互斥。
- Workflow 恢复是整图重放，但依赖现有幂等标记跳过已完成文档；不承诺节点级检查点恢复。
- legacy Run 不自动重排，管理员可在 Run 详情中识别 `interrupted` 状态后按既有流程处置。
