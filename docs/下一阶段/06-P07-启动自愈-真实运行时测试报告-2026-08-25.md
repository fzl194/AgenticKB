## 一、原始交付审查发现（已修复）

### CRITICAL：startup resume 阻塞 lifespan

- 原实现：`recover_startup_runs` 内 `await asyncio.gather(to_thread(resume))`，而 `jobs.run.resume` 是分钟级同步整图重放。
- 后果：uvicorn lifespan 不结束 → 8901 不开始服务 → `deploy-server.sh` 的 120s 健康检查必然超时 → **每次带 workflow 僵尸 Run 的重启都判部署失败**。
- 修复（`705e5eb`，TDD）：
  - `recover_startup_runs` 只做原子标记（毫秒级，lifespan 同步等待，保证服务可用前旧 Run 已置 interrupted）；
  - 新增 `schedule_startup_resumes`：恢复任务 `asyncio.gather` 后台执行，模块级集合持强引用防 GC；
  - 新增用例锁定「标记阶段零 resume / 调用方不被挂起的 resume 拖住」。
- 单测 36 项通过（原 35 + 新 1）。

### 已核实无问题的点

- `mining_runs` PG DDL 有 `domain` 列（`002_mining_runtime_postgresql.sql:18`）——`WHERE domain = %s` 合法。
- 两个旧 schema 测试库（`coremasterkb_domain_test`/`coremasterkb_test`，无 `execution_engine` 列）为空表；若被启用域映射，UPDATE 会报错进 `failed_domains` 容错跳过，不阻断启动。
- `runs.py` 的 `_mark_resume_failure`（daemon 线程逃逸异常标 failed）与线程启动失败释放域锁 + 500：逻辑正确。
