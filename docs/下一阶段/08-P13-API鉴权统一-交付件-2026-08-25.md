# 08 · P13 API 鉴权统一：S0 + S1 交付件

> 日期：2026-08-25
> 分支：`codex/fix-p13-api-auth-unification`
> 范围：P13 的 S0（部署面、凭据与 CORS）和 S1（Mining API 默认拒绝）。
> 本交付件不包含合并或发布操作。

## 交付结果

### S0：部署面、凭据与 CORS

- `docker-compose.yml` 将 LLM、Mining、Serving、MCP 和主控端口全部限制为 `127.0.0.1` 宿主机绑定；UI 的 `8080` 保持为唯一对外入口。
- 认证配置不再包含 JWT、内部校验凭据或 bootstrap 密码的实际值；`auth.yaml` 只声明以下部署环境变量：
  - `CMKB_JWT_SECRET`
  - `CMKB_INTERNAL_VERIFY_SECRET`
  - `CMKB_BOOTSTRAP_ADMIN_PASSWORD`
- Compose 将上述变量注入同一容器内的各服务；`.env.example` 仅提供空字段和配置说明，不提供任何有效凭据。
- 主控认证中间件支持 `*_env` 配置字段。若 `enabled: true` 但环境变量未解析为有效凭据，受保护请求返回 `503 auth misconfigured`，不会退化为匿名放行。
- Mining、主控与 LLM 的 CORS 改为显式来源列表，默认仅允许本地 UI 来源。Mining 在启用 credential CORS 时拒绝通配符来源。

### S1：Mining API 默认拒绝

- 新增全局 Mining API 认证中间件：所有非豁免 `/api/*` 路由必须先完成 `X-KB-User + X-Internal-Auth` 身份认证。
- 认证后的用户写入 `request.state.authenticated_user`；既有 `current_user` 复用该结果，避免全局中间件和路由依赖重复写入用户记录。
- 仅保留以下例外：
  - 匿名：`GET /health`
  - service-only：`POST /api/kb/auth/identify`、`POST /api/kb/auth/verify`、`POST /api/kb/admin/reload-auth-config`
- service-only 例外不会绕过内部凭据校验；其路由仍独立验证 `X-Internal-Auth`，从而保持登录与凭据热重载链路可用。
- `/api/system/status` 已纳入认证，不再匿名可读；Mining 的 `/docs`、`/redoc`、`/openapi.json` 已关闭。
- 内部凭据比较改用常量时间比较，减少两处实现漂移与时序差异。

## 验证

- `knowledge_mining/tests/test_api_auth_guard.py`：覆盖默认拒绝、身份复用、精确白名单、service-only 内部校验、代表 legacy 路由、全量路由表匿名拒绝、CORS 和文档关闭。
- `knowledge_mining/tests/test_deployment_auth_surface.py`：覆盖 Compose 回环端口、单一有效环境映射及 Git 跟踪认证配置不含实际凭据。
- `main_control_service/tests/test_auth_middleware.py`：覆盖环境变量凭据解析、缺失凭据时 fail-closed，以及既有 JWT/CORS 行为。
- `docker compose config --no-interpolate`：确认最终 Compose 渲染中保留所有认证/CORS 环境变量及回环端口绑定。

## 已知运行前置与回滚

- 部署或重启前，必须通过未跟踪 `.env`、部署平台 Secret 或等价机制提供三个 `CMKB_*SECRET/PASSWORD` 值；不提供时服务将安全地拒绝受保护请求。
- 当前 `enabled: false` 或缺少 `auth.yaml` 仍保留为本地开发透传模式；Compose 已将所有后端端口绑定到回环，不能将这一模式用于直接暴露后端端口的部署。
- 回滚代码时应同时恢复旧端口策略、认证配置策略和服务内缓存，不能仅回滚单个服务，否则网关与 Mining 的内部凭据会不同步。
