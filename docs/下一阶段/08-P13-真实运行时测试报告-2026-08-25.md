## 四、环境注意事项（Windows 测试机特有 / 升级须知）

1. **MSYS 路径转换**：Git Bash 下 `bash deploy-server.sh` 会因 `/app/...` 被改写为 `C:/Program Files/Git/app/...` 导致 `verify_mounted_configs` 失败。需 `MSYS_NO_PATHCONV=1 bash deploy-server.sh`。脚本目标为 Linux 服务器，不受影响；建议脚本头注释注明。
2. **compose 项目名错位**：本机曾用默认项目名（目录名）`docker compose up`，与脚本 `-p cmkb` 不一致 → 容器名冲突。清理 `docker rm -f cmkb` 后重跑即可。服务器上不存在此问题。
3. **升级须知（重要）**：存量部署若 auth.yaml 仍是 `change-me-*` 占位符（enabled: true），升级到本分支后主控**全站 503**（占位符视为无效凭据，有意 fail-closed）。必须执行一次 `bash deploy-server.sh`（或手工等价初始化）生成真实凭据后方可恢复服务。
4. **admin 密码不受影响**：`seed_initial_admin` 幂等——库中已有 admin 时 bootstrap 新密码不覆盖（实测旧密码登录正常）。
5. **未初始化凭据时 `/health` 也 503**：属 fail-closed 设计（503 检查先于所有白名单），部署脚本顺序保证；绕过脚本直接 `up` 会得到明确报错而非静默放行。
6. llm 8900 / mcp 9000 / serving 8081 匿名面现状：回环绑定后已不构成外部暴露；容器网络内的服务间鉴权属 P13 S2+ 范围。
