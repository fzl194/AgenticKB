## 0. 修复了什么（业务语言）

**建库即不可检索的静默事故**：此前所有走范式挖掘（全量基线）建的知识库，建成后关键词、语义全都搜不到任何东西，但每个环节都显示"成功"。三层原因：

1. **卡片入库 bug（本批主修）**：新挖掘链的"切片"环节提前把切片存库；最后"资产入库"环节的老判断逻辑一看"切片已有人存过"就以为"这活干过了"，把检索卡片和向量整批跳过——每篇文档"入库成功"，库里卡片 0 张。
2. **嵌入服务欠费**（用户充值当日恢复，非代码问题）。
3. **验收门禁缺失**：构建验收只查"有没有切片"，不查"有没有卡片/向量"。

配套落地（已拍板决策）：建库默认全量基线范式、库详情页可见"检索就绪度"四档、没卡片/没向量的 build 不许称验收通过（嵌入不可用时显式留痕放行）。

- `pipeline.py:898` `persist_document_assets`：units/relations/embeddings 的插入全部写在 `count_segments_by_snapshot(snapshot_id)==0` 分支内；v2 链 `segment_compile` 经 `PgSegmentStore.replace_for_snapshot`（`segment_compiler/repositories_pg.py:70`）**预写切片** → 恒走 else 分支 → 三类资产静默丢弃。

- 修复前基线 E2E（用户充值后实测）：run completed、embedding 算子 completed，新快照 0 units / 0 embeddings。

## 5. 门禁语义（冻结）

- 能力校验只作用于 **本 run 产出的快照**（NEW/UPDATE/RESTORE）；父 build carry-forward 快照按其当时能力验收过，不重检
- 含 embedding 能力且嵌入算子 fallback/skipped → `summary.embedding_fallback=true` 留痕放行（readiness 封顶 lexical_ready）
- legacy build 无签名 → 三条旧检查（父存在/有活跃快照/每快照 ≥1 切片），行为不变
- 存量库**不重挖**（已拍板）；补索引 = 手动 force_redo 重新挖掘
