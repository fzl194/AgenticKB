## 0. 最终形态（用户口径，一句话版）

**库拥有"检索范式"，用户拥有"MCP"。**

- 知识库绑定自己的检索范式 → 决定 MCP **检索 tool** 搜这个库时走哪条管线
- 用户管理自己的 MCP：一把密钥 + 开放哪些库 + MCP/工具描述文案（后项批次7）
- Agent 持钥连接，只看到开放库；**开放 1 个库时连库名都不用传**，直接走该库管线
- 列文件/看内容/上传文件等是 MCP 级通用 tool，与范式无关（批次7）

```
知识库（库级）                      用户（用户级）
┌────────────────────┐            ┌──────────────────────────────┐
│ 基站手册库 → 范式:快速向量检索      │ 张三的 MCP 配置：                │
│ 设备手册库 → 范式:篇章增强检索      │  ├─ 密钥（一把，重建即轮换）       │
│ 未绑定库   → 域默认 → 官方默认      │  ├─ 开放库清单（勾选）            │
└────────────────────┘            │  └─ 描述文案（批次7 可编辑）       │
                                  └──────────────────────────────┘
Agent ──持钥──► MCP（张三视图）──► 只见开放库；search 不传库=搜全部开放库，
                                      只开放 1 库=免传直接走该库管线
```

## 2. 搜索解析规则（库为中心，定稿）

MCP `search(query, kb_names?)`（kb_names 可选）：

```
① 鉴权：密钥必须有效（无钥/错钥/已轮换 → 401，无匿名模式）
② 开放库 = 用户 MCP 配置勾选的库 ∩ 用户仍有权限的库（权限变动即时收窄）
③ 目标库：
   - kb_names 传了 → 必须都在开放库内（不在 → 报"未开放"）
   - 没传 → 全部开放库
   - 开放库为 0 → 报"未开放任何知识库"（不落任何检索）
④ 管线选择（检索 tool 走哪条范式）：
   - 目标库全部绑定了同一条范式 → 用它（source=library）
   - 否则 → 域默认范式（source=domain）→ 官方默认范式（source=official）
   - 都没有 → 明确报错"该域未配置检索范式"（不回落 legacy）
⑤ 范围执行：管线内 scope 节点留空 → 注入目标库；写死 → 按图内（高级用法）
   授权一律按密钥用户过 KbAccessService（不可读整单 403，不泄露哪个）
```

多库绑不同范式不各跑各的再拼（一次搜索一次管线执行，成本与排序可控）——"绑得一致才用库级，否则落默认"。

## 3. 模块设计（批次5 = A）

### 3.1 密钥（用户级，一人一钥）

**表** `databases/kb/schemas/008_mcp_access.sql`（域库）：

```sql
CREATE TABLE IF NOT EXISTS mcp_access (
  user_id       TEXT PRIMARY KEY REFERENCES kb_users(id),  -- 一人一行=一人一钥
  key_hash      TEXT NOT NULL,          -- sha256(明文)；不存明文
  key_prefix    TEXT NOT NULL,          -- 明文前 8 位，界面识别用
  status        TEXT NOT NULL DEFAULT 'active',
  created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
  last_used_at  TIMESTAMPTZ,
  rotated_at    TIMESTAMPTZ             -- 上次轮换时间（重建即轮换，旧钥立即失效）
);
CREATE TABLE IF NOT EXISTS mcp_open_kbs (
  user_id       TEXT NOT NULL REFERENCES kb_users(id),
  kb_id         TEXT NOT NULL REFERENCES knowledge_bases(id),
  granted_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
  PRIMARY KEY (user_id, kb_id)
);
```

- 形态：`kbm_` + 32 字节随机 hex；明文仅生成响应显示一次
- **轮换语义**：重新生成 → 覆盖 key_hash + rotated_at，旧钥立即 401（无并存期）
- 按域存（用户体系分域；用户基本单域，跨域各建）

**API**（mining，登录态）：
- `GET  /api/kb/users/me/mcp-access?domain=` → `{key_prefix, created_at, rotated_at, last_used_at, open_kbs: [...]}`
- `POST /api/kb/users/me/mcp-access/rotate` → 返回新明文（一次）
- `PUT  /api/kb/users/me/mcp-access/open-kbs` `{kb_ids: [...]}` → 全量覆盖开放库勾选（服务端校验本人可见库，非可见 → 400）

**校验 API**（internal-only，X-Internal-Auth，供 MCP 调）：
- `POST /api/kb/auth/mcp-key-verify` `{domain, key}` → `{username, open_kb_ids}` / 401
  - active+命中 → 顺带节流更新 last_used_at（60s）；开放库在响应里带出，MCP 免二次查

### 3.2 库级默认检索范式

**DDL** `009_kb_default_paradigm.sql`：`ALTER TABLE knowledge_bases ADD COLUMN IF NOT EXISTS default_paradigm_id TEXT;`（跨库无 FK，应用层校验）

- 写路径：mining `PATCH /api/kb/{kb_id}` 增 `default_paradigm_id`；非空时调 serving `GET /api/v1/paradigm/{id}` 校验（published active + assemble 终点 + 同域），不满足 400
- 读路径：serving 侧解析（§2 ④）；库级范式失效（归档）→ 跳过降级，响应 `degraded:true, degradedFrom:"library"`

### 3.3 Java：运行时 kbIds + 官方默认 + resolve 增强

- `RunArgs` + `List<String> kbIds`；`POST /api/v1/paradigm/{id}/search` 与 inline run 接 body `kbIds`
- ScopeResolveOperator 注入：`params.kbIds 非空 ? 图内 : ctx.requestKbIds()`；空 → 域级（现状）
- `GET /api/v1/paradigm/resolve` 增 `kbIds` 参数：按 §2 ④ 返回 `{paradigmId, source: library|domain|official, degraded?}`——**四层判定逻辑收敛在这一个端点**，MCP 只调它
- 官方默认范式：seeding `system-official-default`（query_embed→fts→rrf→rerank→assemble 最简可发表图；不占域默认槽）。检索质量对齐 legacy 是批次8（C）四能力算子化的事，本批仅兜底可达
- **MCP 侧 legacy 回落本批删除**：resolve 无果 → 报错，不再走 /api/v1/search。Java 固定链路与 /api/v1/search 本批保留（kb-ui 搜索页仍用），C 批删除

### 3.4 MCP 接线（mcp_server）

- 鉴权：每个 tool 读 `Authorization: Bearer kbm_...` → 调 3.1 校验 API → 得 `{username, open_kb_ids}` → 全部 serving 调用附 `X-KB-User`；无/错钥 → 401（tools/list 也 401——无匿名）
- `search_knowledge` 参数：`query` 必填 + `kb_names` 可选（同域内库名唯一，按名解析 id；§2 全规则）
- client.py 路由改为：resolve（带目标库）→ 范式执行；不再有 legacy 分支
- `get_segment_fulltext` 同步带身份透传
- （描述文案可编辑、list_documents/get_document/upload 工具族 = 批次7）

## 4. 安全设计

- 明文只出现一次；库内仅 sha256；日志只记 prefix；轮换无并存期
- 校验 API internal-only（X-Internal-Auth），MCP 与 mining 同容器/网段
- 开放库 ∩ 实时权限：权限被收走后开放清单自动失效（resolve/authorize 双重校验）
- kb_names 与注入 kbIds 一律过 KbAccessService；整单 403 不泄露具体哪个库

## 5. 兼容性

- 已发布范式（kbIds 写死）：行为不变（注入只对留空生效）
- kb-ui 搜索页（legacy）：本批不动（C 批切范式）
- Java mvn 383 项：RunArgs/Controller 加字段不改语义 + 新增注入单测
- MCP 现有匿名调用方：**预期内破坏**（强制密钥是拍板决策；部署公告提醒建钥）
