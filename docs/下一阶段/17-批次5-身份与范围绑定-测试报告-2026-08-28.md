## 0. 交付了什么（业务语言）

1. **每个用户一把 MCP 接入密钥**：个人设置 → MCP 接入，生成/轮换（旧钥立即失效）、勾选开放哪些知识库。Agent 拿密钥连 MCP，以你的身份检索——私有库对 Agent 可见（此前匿名只能搜公开库）。
2. **无密钥不再放行**：MCP 全部工具调用强制验密钥（此前零鉴权）。
3. **知识库可绑自己的检索范式**：KB 设置页选择；搜这个库自动走它绑的管线。
4. **检索范式与库解耦（菜谱+运行时范围）**：范式范围留空 = 检索时按"开放库/请求指定的库"注入；写死 = 专属范式（图内优先，请求值被忽略并留痕）。
5. **四层管线解析**：库级绑定一致 > 领域默认 > 官方默认（本次新增 seeding，控制库此前 0 条范式）；全无 → 明确报错。**MCP 侧旧链路回落已删除**（Agent 侧一步到最终形态；Java 固定链路保留给网页搜索页，C 阶段删）。
6. **搜索免传库名**：只开放一个库时 Agent 只传问题即可。

**与方案的差异（1 项，已接受）**：`tools/list`（工具清单）对未鉴权调用仍可见——FastMCP 1.x 框架层无请求级钩子；工具**调用**已全部强制验密钥，清单仅含名称/描述不含数据。批次7 工具族动态化（FastMCP 升级/自定义 list_tools）时一并收口。

**踩坑记录**：
- 容器内调 nginx 须 `127.0.0.1:80`（8080 是宿主映射；`localhost` 解析 ipv6 会被拒）
- auth_guard 中间件白名单：新增 service-only 端点必须加进 `_SERVICE_ONLY_ROUTES`，否则路由层的 X-Internal-Auth 校验根本到不了
- FastAPI 依赖函数手动调用需 `await`（`get_kb_db(request)` 返回 coroutine——mock 测试盲区，E2E 实测抓出）
- Java text block 内不能用 `+` 拼接字符串常量（会破坏 JSON 常量，编译期不报错、schema 运行期炸——由 OperatorCatalogTest 抓出）

## 4. 安全语义（冻结）

- 明文密钥仅生成响应出现一次；库内仅 sha256；日志仅 prefix
- 每次工具调用实查验密钥（不做身份缓存）——吊销/轮换零窗口；mining 侧 last_used_at 节流避免写放大
- 开放库 ∩ 实时权限双重校验（verify 带出 ∩ authorize 兜底）；权限收窄即时生效
- kb_names/kbIds 一律过 KbAccessService，不可读整单 403 不泄露具体库
