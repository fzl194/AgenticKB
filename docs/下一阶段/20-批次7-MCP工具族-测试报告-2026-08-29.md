## 0. 交付了什么（业务语言）

1. **左侧新增"MCP 接入"独立页面（全员可见）**：最上面是给 Agent 用的**接入配置 JSON**（拼好地址与密钥，通用/dify 两种格式一键复制），往下依次是密钥管理、**工具开关**（六个工具逐个开/关）、开放知识库勾选、**提示词与工具说明编辑**。
2. **Agent 能用的工具从 2 个扩到 6 个**：搜知识（原有）、列出我的库、列库内文件、读文件内容、取证据原文（原有）、**上传文件入库**（不自动挖掘——用户 D2 拍板，上传后提示去界面挖）。
3. **工具清单"按人变脸"**：不同用户连同一个 MCP 地址，各自看到自己开启的工具、自己改写的工具说明；关掉的工具从清单里彻底消失、调用即拒。
4. **无密钥连工具清单都拿不到**（批次5 遗留的 tools/list 匿名可见收口）。
5. **知识库"设置"页的检索范式下拉移除**（用户指令：已有独立"检索" tab，设置里不再重复）。
6. **底层升级到 FastMCP 3.4.7**：pyproject 早就声明 >=2.0、容器也装着，但代码一直 import 旧的内置 1.x——这笔债本次清掉（升级同时拿到了请求头访问与中间件能力，动态化才成为可能）。

## 4. 过程事故与坑（记档）

1. **verify 响应漏字段**（E2E S4 抓出）：db 层返回了 open_tools 但路由手写响应构造丢弃——mock 测试盲区，真链路 E2E 兜底价值再次验证。
2. **worktree 未构建 jar 导致 deploy 回装镜像里的 8/24 老 jar**（S6 失败根因）：worktree 部署前必须 `mvn -DskipTests package`（deploy 只搬产物不构建）。已固化流程。
3. **凭据随机化后部分重启造成进程间 secret 错位**（登录 401 伪装）：deploy 每次运行都会随机化 internal_verify_secret；手动重启单个服务后，未重启进程持旧值 → 全服务重启即愈。
4. **fastmcp 3.x 不读 MCP_HOST/MCP_PORT env**：不显式传参会静默起在 127.0.0.1:8000。
5. **软删库占用 (domain,name) 唯一名**：E2E 重跑需换库名。
