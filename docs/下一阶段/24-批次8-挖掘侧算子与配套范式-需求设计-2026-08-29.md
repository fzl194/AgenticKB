## 1. 原始需求、目标与非目标

用户要解决的不是“把已有算子都用上”，而是端到端回答：哪些资产值得生产、检索侧怎样消费、实际质量能否覆盖成本。挖掘侧必须做到：

1. 保留结构真相，充分利用 ParseIR 的标题树、父子关系、表格网格、代码/列表/公式、页码和 source span；
2. 将“原始证据”“结构化可查询资产”“搜索表示”分层，不能把 retrieval unit 当成唯一知识形态；
3. 默认生产线不调用生成式 LLM；离线 LLM 增强必须独立、可跳过、可降级、可追溯；
4. 每个资产都明确消费者。没有检索消费者或业务增益闭环的 enrich、篇章修辞关系等能力直接下线；
5. 形成 4 套挖掘预置，并与检索侧 2 套预置形成明确多对一配套；
6. 当前为可清理测试环境，采用 clean break，不背负旧资产和旧 manifest 的兼容成本。

本批明确不做：GraphRAG、RAPTOR、多 embedding 模型/图片模型/代码模型、在线 LLM 查询理解、正式的算子晋级平台。实体/本体研究代码是唯一保留但完全隐藏的研究例外。

## 2. 当前代码事实与必须消除的断点

### 2.1 当前实现不是目标架构

当前目录 `knowledge_mining/mining/workflow/operators/catalog.py` 注册 17 个算子，默认检索资产支线实际为：

```text
document_parse → segment_compile
  → enrich → discourse_line → contextual_retrieval_enrich
  → retrieval_unit_build → embedding → asset_persist
```

`document_parse` 和 `segment_compile` 已接入新 ParseIR/segment compiler，但 `workflow/handlers/document.py` 随后把结果兼容投影回旧 `DocumentContext`；后续检索资产算子仍复用旧 pipeline stage。这一兼容拼接必须移除，不能在新算子外再保留一条旧资产生产暗链。

### 2.2 已查实的数据断点

| 位置 | 当前事实 | 本批要求 |
|---|---|---|
| `contracts/parse_ir/types.py` | 已有 `TableAsset/TableCell`、header、row/column span、caption/footnote、cell source span | 作为表格结构真相直接投影，不再先压扁后猜回 |
| `segment_compile` | 支持 `tableView=whole/rows/both`，标题路径注入 | 保留并强化结构边界、稳定 parent/container/ordinal/source refs |
| compatibility projection | `table_row` 会收敛成 legacy `table` block type | 删除兼容投影造成的信息损失 |
| 旧 table-row builder | 期待 `columns + rows[dict]` 的另一种结构 | 由新 projector 直接消费 ParseIR TableAsset/compiled table views |
| `RetrievalUnitData` | unit type、target、source refs 已有雏形，但 `generated_question/entity_card` 与确定性投影混在一起 | 更换为统一 representation 契约；LLM/实体职责拆出或隐藏 |
| `asset_retrieval_embeddings` | 主要记录 model/provider/text_kind/dim/hash，当前统一 `text_kind=full` | 冻结 policy、strategy、真实 input hash、provider capability 和 fallback |
| `asset_persist_handler` | 调用 legacy `persist_document_assets`，依赖兼容 DocumentContext | 改为三面资产事务写入，不再调用旧 stage 链 |
| readiness | 当前偏重 units/embeddings 数量 | 改为按文档/快照/Build 声明四类可用能力事实 |

## 3. 目标资产架构与主数据流

### 3.1 三面资产

```text
源证据面 Source Projection
  ParseIR / source spans / raw segments / source object
        │
        ├── 结构化面 Structured Projection
        │     structure nodes/edges + typed assets + schema/readiness
        │
        └── 搜索面 Search Projection
              retrieval representations + FTS fields + embeddings
```

- 源证据面是引用和逐字核验的真相；
- 结构化面支持 `inspect_knowledge`、`navigate_structure`、`query_structured_asset`；
- 搜索面支持 FTS/dense 模糊发现；
- 三面通过 opaque public ref、内部 target ref、source span 和 `canonical_evidence_id` 关联；
- retrieval representation 只是搜索代理，不得被当成最终证据直接返回。

### 3.2 默认零生成式 LLM 生产线

```text
input_ingest
→ document_parse
→ segment_compile
→ retrieval_unit_project
→ embedding（关键词预置可省略）
→ asset_persist
→ mining_finalize
```

可选增强分别插在 projector 与 embedding 之间：

```text
… → retrieval_unit_project → query_expansion_generate → embedding → …
… → retrieval_unit_project → hierarchical_summary_generate → embedding → …
```

本批不提供 query alias 与 summary alias 同时开启的官方排列组合预置；用户自定义图仍须通过资源预算和契约校验。

### 3.3 新的文档态契约

删除 handler 间继续传递 legacy `DocumentContext` 的做法。执行器可继续以 immutable `DocumentState` 承载，但 `context` 必须升级为明确版本的 `MiningDocumentBundle`，至少包含：

| 字段 | 语义 |
|---|---|
| `document_ref/snapshot_ref` | 文档和不可变快照身份 |
| `parse_ir_ref` | 已通过质量门的 ParseIR 快照引用 |
| `compiled_segments[]` | 结构保真的可引用段/块，不是旧兼容段副本 |
| `document_facts` | token、层级数、section/segment/asset 数等确定性统计 |
| `structure_projection` | nodes、可追溯 edges、typed assets、schema |
| `representations[]` | 统一搜索表示 |
| `embeddings[]` | 与表示一一关联的向量派生资产 |
| `capability_facts` | 本文 §7 的 readiness 事实 |
| `diagnostics` | skipped/degraded/invalid/cost/version 统计 |

工作流 SlotType 应补充相应 typed batch，或至少使 `DOCUMENT_BATCH` 内部只允许该版本化 bundle；不得用“先降级为旧对象、再从 metadata 猜字段”的方式过渡。

**序列化边界（2026-08-29 审查追加）：**bundle 在 worker 间传递时 `compiled_segments[]` 不随 bundle 全量序列化——大文档场景下 segments 先落 staging（或按 snapshot ref 引用），bundle 内只携带引用与计数；`parse_ir_ref` 保持引用语义，禁止把整个 ParseIR 塞进 bundle。

## 5. 逐算子需求

### 5.1 `input_ingest`

**现状锚点：** `workflow/operators/catalog.py` 将其设为 fixed，输出 `RAW_FILE_BATCH`。

**目标契约：**

- requires：运行输入、KB/文档选择、不可变执行身份；
- provides：`raw_files`，每项包含 document identity、revision/source object、mime/size/hash；
- options：无业务策略；选择范围来自 Run 请求，不写进范式；
- failure：输入不存在或越权 `FAIL_FAST`；单文档冻结失败由后续 parse 标记 document failure；
- idempotency：相同 run input + source revision 产生相同 frozen identity。

**改造：**保留已有冻结输入/失效检查成果；删除任何与旧批次挖掘通道或旧资产 stage 的隐式耦合。输出不能携带未授权本地路径到公开结果。

### 5.2 `document_parse`

**现状锚点：** `workflow/new_chain_services.py` 已调用新 parse facade，但 handler 随后兼容投影成旧 `DocumentContext`。

**目标契约：**

- requires：`raw_files`；
- provides：`parsed_documents`（含 `parse_ir_ref`、parser provenance、quality facts）；
- options：保留 `qualityProfile/maxBackendAttempts`；
- failure：单文档解析或质量门失败为 `SKIP_DOCUMENT`，不能产生可发布 search/structured assets；
- idempotency：source hash + parser plan/version + rule fingerprint。

**改造：**删除 handler 内 legacy projection；ParseIR 的 element/container/source span/typed assets 必须原样可达后续 compiler。图片语义生成不在本批新增。

### 5.3 `segment_compile`

**目标职责：**只从 ParseIR 编译结构保真的内容块和确定性结构索引，不生成搜索别名、向量或 LLM 关系。

**必须输出：**

- document/section/element/segment 的稳定内部 target；
- `parent_ref/container_ref/section_ref/ordinal`；
- `source_span_refs/page/from/to`；
- `content_type`：`prose|table|table_row|list_group|code_block|formula|figure_caption|heading|navigation`；
- table row 对应 `table_ref`、header cell refs、caption/footnote refs；
- 文档统计：token、section/segment/asset 数、最大层级、各类型占比；
- 仅对原文明确存在的 caption、footnote、hyperlink、explicit reference 生成可追溯 edge。

**默认参数：**继续支持 `maxTokens/minTokens/mergeAdjacentParagraphs/injectHeadingContext/tableView/includeFigureCaptions`。结构边界优先，token 上限为兜底；不得跨表格、代码块、列表容器或明确章节边界机械合并。

**禁止：**生成 LLM `semantic_role`、因果/对比/展开等修辞边、永久 small/medium/large 标签。

### 5.4 `retrieval_unit_project`

这是搜索表示编译器，不是入库器、LLM 生成器或最终返回路由。

#### 统一 `RetrievalRepresentation` 契约

| 字段 | 要求 |
|---|---|
| `representation_id/key/version` | 确定性、可幂等重建 |
| `representation_type` | 本节固定枚举 |
| `content_type` | 源内容类型，不与 representation type 混用 |
| `content_text` | 可检索文本；不得成为无来源的新事实 |
| `structural_context` | 标题 breadcrumb、表头、caption 等确定性上下文 |
| `target_type/target_ref` | hydrate 时解析的 canonical target |
| `canonical_evidence_id` | 同源 raw/alias/多视图聚合键 |
| `source_refs[]` | document/section/segment/element/table/cell/span 引用 |
| `parent_ref/container_ref/context_group_id/ordinal` | small-to-big 和邻窗所需事实 |
| `lexical_eligible/dense_eligible/returnable` | 分别声明 FTS、向量、能否直接作证据 |
| `facets` | KB、document、path、section、page、content/asset type、date 等确定性过滤字段 |
| `provenance` | projector/version/source hash；派生别名还含模型/prompt |

#### 类型矩阵

| representation type | 来源 | 默认 FTS | 默认 dense | returnable | canonical target |
|---|---|---:|---:|---:|---|
| `prose` | 正文 compiled segment | 是 | 是 | 是 | segment/element |
| `section` | 真实章节标题 + 有界直接内容投影 | 是 | 是 | 是 | section |
| `document` | 文件名/标题/描述等来源事实 | 是 | 是 | 是 | document |
| `table` | caption + 表头 + 有界整表文本 | 是 | 视长度/质量 | 是 | table |
| `table_row` | 表头 + 本行 cell 文本 | 是 | 是 | 是 | table row/table |
| `list_group` | 列表标题/路径 + 完整列表或有界分组 | 是 | 是 | 是 | list container |
| `code_block` | 章节路径 + 完整代码块 | 是 | 是（当前文本模型） | 是 | code block |
| `formula` | 路径 + raw/LaTeX/MathML 可用文本 | 是 | 是（当前文本模型） | 是 | formula |
| `figure_caption` | 原始 caption/附近明确 mention | 是 | 是（当前文本模型） | 是 | caption/figure |
| `query_alias` | `query_expansion_generate` | 可配置，默认是 | 可配置，默认是 | **否** | 源 canonical evidence |
| `summary_alias` | `hierarchical_summary_generate` | 可配置，默认是 | 可配置，默认是 | **否/derived** | section/document + source refs |

heading/navigation/TOC 可以成为结构节点和 facet，但默认不单独形成正文 representation。section/document representation 只使用可追溯标题和元数据，不能为了“文档级检索”偷偷生成 LLM 摘要。

**同源规则：**不同 representation 可指向同一证据；`canonical_evidence_id` 必须一致。table whole 与 row 是不同 canonical target，但 row 需保留 table container ref。projector 不生成 embedding，也不写数据库。

### 5.5 `query_expansion_generate`

**用途：**离线 Doc2Query 风格增强，让用户问题形式更容易命中源证据；产物只是检索别名。

**资格门默认：**

- `prose`：有完整陈述，归一化后不少于约 80 tokens，非纯标题/导航；
- `table_row`：至少一个 header-value 对且非空值足够；
- `list_group`：列表包含可独立回答的事实项；
- `section/document/table`：默认关闭，避免宽泛问题污染；
- `code_block/formula/figure_caption/heading/navigation`：默认关闭；
- 以上阈值是 versioned default policy，用户可在算子参数按类型覆盖。

**输出校验：**LLM 必须返回 `SKIP` 或 `question + answer_span + source target`。`answer_span` 需在允许的源范围内做 Unicode/空白归一化后精确匹配；generation context 只帮助理解，不能扩大证据范围。默认 `maxAliasesPerTarget=1`，并做 target 内、文档内、canonical evidence 三层去重。

**失败语义：**SKIP、模型失败、格式错误、answer span 不匹配、去重丢弃分别计数。算子整体降级时保留基础 representations，发布 `query_alias_ready=false/degraded=true`，不得让文档挖掘失败。

**幂等：**source hash + eligibility policy version + prompt/model/version + normalized question。

### 5.6 `hierarchical_summary_generate`

**用途：**服务“全文总结、主题归纳、跨章节综合”等长文档全局查询，不服务普通局部事实召回。

**规则：**

1. 只消费真实标题树、section source refs 和确定性统计；
2. 叶子内容未达到配置门槛直接跳过，不逐小段强制总结；
3. 自底向上生成 section/document summary；
4. 每个 `summary_alias` 绑定目标 section/document 和覆盖的 source target/span；
5. 摘要标记 `derived=true`，默认不可作为逐字引用；hydrate 必须能回到源证据；
6. 局部变化只重建受影响 section 及祖先；
7. source hash + tree path + prompt/model/version 构成幂等签名；
8. LLM 失败只使 summary capability degraded，不阻断基础资产发布。

这不是 RAPTOR：本批没有语义聚类、递归 cluster tree、跨层向量路由，因此代码、UI、文案均不得命名 RAPTOR。

### 5.7 `embedding`

保留一个 embedding 节点，但执行的是版本化 per-representation policy，而不是 pipeline 级单一 mode。

#### 策略枚举

- `skip`：不生成向量；
- `isolated`：只嵌入 `content_text`；
- `structural`：用有界、确定性的 breadcrumb/header/caption + content 构造输入；
- `contextualized`：使用 embedding provider 明确支持的非生成式上下文输入能力；不得恢复逐段 LLM contextualizer；
- `late_chunking`：同一 context group 长上下文编码后聚合各 span；只在 provider/model 能力明确时启用。

#### 默认矩阵

| 类型 | 默认策略 |
|---|---|
| prose/section | `structural` |
| document | `isolated` |
| table/table_row/list_group/figure_caption | `structural` |
| code_block/formula | `isolated` |
| query_alias/summary_alias | `isolated` |
| 超长 whole document/raw section | `skip` |

算子参数允许按 `representation_type/content_type/has_ordered_context/has_source_span` 覆盖，规则必须有 priority、policy version、显式 fallback。当前所有 dense eligible 单元共享一个文本 embedding 模型、维度和向量空间；query 侧每次只嵌入一次。不得增加多模型路由参数面。

每条 embedding 必须记录：representation id、provider/model/version/dimension、strategy、policy version、input hash、source/context group hash、fallback、created_at。provider 不支持策略时编译失败；只有 policy 显式声明 fallback 才可降级。重跑按签名局部补齐。

### 5.8 `asset_persist`

**职责：**在单文档快照事务边界内写入三面资产，而不是重新计算上游能力。

建议保留并 clean-break 重建以下物理表/逻辑等价物：

| 表/投影 | 关键内容 |
|---|---|
| `asset_raw_segments` | 源内容块、section/container/ordinal/source span；删除旧修辞角色依赖 |
| `asset_structure_nodes` | document/section/element/segment/table/list/code/formula/figure 等节点 |
| `asset_structure_edges` | parent/child/order、caption、footnote、explicit reference；不存 LLM RST |
| `asset_structured_assets` | asset ref/type/schema version/readiness/source refs |
| `asset_table_cells` | table ref、row/column/span、header、raw/normalized value/type/formula/source span |
| `asset_retrieval_units` | §5.4 representation 字段、FTS 字段、canonical target/facets |
| `asset_retrieval_embeddings` | §5.7 向量 provenance |
| snapshot/build readiness | §7 四类能力事实及 degraded diagnostics |

所有 public ref 必须不透明、不可枚举且受 KB/快照授权校验。内部 UUID 可存但不得从 MCP 直接暴露。写入使用 staging/upsert + 完整性校验 + 原子切换；失败不得留下“部分新资产却标记 ready”的快照。

**FTS 分词契约（2026-08-29 审查追加，命门级）：**当前检索侧 `websearch_to_tsquery('simple', ...)` 的 `simple` 配置不做中文分词；索引/查询两侧分词不同源会导致中文 FTS 无声 miss。约定：索引侧由 `asset_persist` 写入 retrieval units 时用分词器（默认 jieba）预分词生成 tsvector，不依赖 PostgreSQL 分词扩展；查询侧使用**同一分词器同版本**分词后构造 tsquery；分词器名称与版本进入 Build manifest 与检索请求可观测记录，两侧版本错位必须显式报错，不得静默降级。

**DDL 归属约定（2026-08-29 审查追加）：**三面资产新表（本节表列）的 DDL 由 mining 侧唯一维护（幂等 migration）；Java 检索侧只通过 schema version 化的 mapper 消费，不得在 serving 侧建表或改列；schema version 进 Build manifest，Java mapper 与之强校验。

### 5.9 `mining_finalize`

只有实际资产通过校验后才能发布能力。必须检查：

- canonical target/source ref 均可解析；
- lexical eligible unit 已进入 FTS 投影；
- dense eligible unit 的 embedding coverage 符合本预置要求；
- structure edge 两端存在且授权范围一致；
- structured asset schema 有效，table cell/source span 可解析；
- alias 均不可作为 canonical raw evidence，且可回源；
- Build manifest 冻结算子版本、参数、policy、模型和 schema version。

增强算子失败可发布基础能力，但 readiness 和发布摘要必须准确标记 degraded；基础搜索资产或源引用不完整则不得发布为 ready。

### 5.10 `entity_extract`

源码可保留用于研究，但从正式 catalog、handler registry 自动发现、API、UI、seed 和新 workflow compiler 可用集合移除。不得在标准文档 bundle 中声明 `entity_mentions` readiness，也不得由正式 `asset_persist` 默认写入或由检索消费。

### 5.11 `entity_resolve`

随实体研究线隔离，不能成为 `entity_extract` 未在正式图中时自动插入的 protected/fixed 节点。别名归一研究表可保留，但正式 Build manifest、产品能力和 MCP inspect 均不得声明可用。

### 5.12 `entity_relation_extract`

源码保留、正式隐藏。删除 compiler 中为其动态追加 requires 的正式路径；不得把其产物写成 GraphRAG readiness，也不得退化为通用段关系抽取。

### 5.13 `entity_review_gate`

研究代码保留，退出 `_PROTECTED_TYPES` 和正式 global executor/catalog。标准挖掘 Run 不因实体待审暂停，产品不显示 pause step、审核入口或待审计数。

### 5.14 `ontology_induction`

研究代码保留，正式工作流不可选择。不得在基础文档已完成时后台隐式运行，也不得让 ontology 失败影响 search/structure readiness。

### 5.15 `ontology_review_gate`

研究代码保留，退出正式 protected/global chain 和 UI；标准 Run 不产生本体审核暂停状态。

### 5.16 `graph_write`

研究代码保留，退出正式 protected/global chain、Build 发布和产品能力。未来若启用 GraphRAG，必须重新设计实体/关系/社区/证据/查询消费者全闭环，而不是恢复本节点即宣称完成。

以上七个研究算子的共同隔离要求：

- 不注册到正式 catalog 或普通用户 API；
- 不出现在画布、官方预置、新建范式候选、MCP capability、readiness；
- 不由 `asset_persist/mining_finalize` 默认消费；
- 保留代码必须有清楚的 `research/disabled` 边界，防止 Spring/Python 自动扫描误注册；
- 将来启用必须重新完成生产—持久化—检索消费—评测闭环，不能只把开关打开。

### 5.17 `enrich`

直接删除 catalog/options/handler/stage/prompt/tests/UI/preset 以及对 `semantic_role` LLM 结果的消费。确定性 content type 来自 ParseIR/compiler；文档统计来自聚合事实。不得把旧 prompt 挪进 projector 或 persist。旧 enrich 失败被吞却声明 capability 的行为不保留。

### 5.18 `discourse_line`

直接删除 LLM 滑窗关系抽取、RST relation contract/写入、参数和测试，并与检索 `graph_expand` 成对清理数据。只保留原文显式 reference/caption/footnote 等可追溯边，parent/order 等由 compiler 确定性产生。

### 5.19 `contextual_retrieval_enrich`

直接删除“文档前 2000 字 + 当前段前 500 字”的逐段生成和 `retrieval_context/search_text` 旧依赖。结构上下文由 projector 确定性提供，向量输入由 embedding policy 的 `structural/contextualized/late_chunking` 策略构造；不得恢复生成式 LLM fallback。

### 5.20 `retrieval_unit_build`

原名和旧实现直接删除，不保留兼容 handler。raw/table 等确定性投影迁入 `retrieval_unit_project`；问题生成迁入 `query_expansion_generate`；entity card 退出正式线。旧 `RetrievalUnitOptions` 及 `generatedQuestionUnit/tableRowUnit` 混合开关整体删除。

## 6. 结构化数据投影和搜索投影的具体关系

| ParseIR/compiled 资产 | 搜索表示 | 结构化投影 | 检索后的动作 |
|---|---|---|---|
| document | document title/metadata unit | document node/profile | hydrate 可能返回全文或文档概览；`get_document` 精确读取 |
| section | section unit + child prose units | section tree/order | hydrate 返回 parent/window；navigate 查父子/相邻 |
| prose paragraph/segment | prose unit | source node/span | 返回原段或按预算扩父章节/邻段 |
| TableAsset | table + row units | typed table + cells + schema | 模糊命中补表头/caption；严格筛选/聚合走 structured query |
| list | list_group unit | list container/items/order | 返回完整列表或有界分组；可导航 |
| code | code_block unit | code node/language/source span | 返回完整代码块 + 章节 |
| formula | formula unit | formula raw/LaTeX/MathML | 返回公式及附近说明 |
| figure caption | caption unit | figure/caption/mention links | 返回 caption/明确 mention；本批无图片向量 |
| explicit reference | 通常不单独建 unit | reference edge | 命中后可由 navigate 显式跟随 |
| query/summary alias | alias unit | provenance/source refs | 永远回到 canonical source evidence |

结构事实不是全部做成 Top-K unit。parent、child、previous、next、same container 等用于 hydrate/navigate，不能制造大量重复搜索文本。

## 7. Readiness 与发布事实

每个文档快照和 Build 至少声明：

| capability | 成立条件 |
|---|---|
| `search_ready` | 有可解析 canonical source 的 lexical unit；混合预置还需 dense coverage 达标 |
| `structure_navigate_ready` | structure nodes/order/parent/container/source refs 完整 |
| `structured_query_ready` | 至少一个 typed asset 通过 schema 和质量门，可执行白名单 DSL |
| `aggregate_ready` | 目标字段具有稳定 value type/normalized value，且允许 count/sum/min/max/avg 中对应操作 |

增强事实另记 `query_alias_ready/summary_alias_ready` 及 degraded 原因，但不替代四个核心事实。capability 不能由“图里有算子”或 handler 返回 SUCCESS 推断。

## 8. 四套官方挖掘范式

| 预置 | 图 | 用途 | 状态 | 配套检索 |
|---|---|---|---|---|
| 轻量关键词资产 | ingest→parse→segment→project→persist→finalize | 低成本、无向量服务、可接受 lexical-only | 正式可选 | 关键词证据检索 |
| 标准混合资产 | ingest→parse→segment→project→embedding→persist→finalize | 通用知识库默认 | **官方默认** | 标准混合证据检索 |
| 问题别名增强资产 | 标准链 + query expansion（在 embedding 前） | 问法与原文措辞差异大的知识 | 实验、非默认 | 复用标准混合检索 |
| 长文档全局增强资产 | 标准链 + hierarchical summary（在 embedding 前） | 全文总结、跨章节综合 | 实验、非默认 | 复用标准混合检索 |

small-to-big、table、code、list、结构导航不是独立挖掘范式；它们是标准资产契约的一部分。旧 `minimal/fast_retrieval/discourse_only/entity_graph/hybrid_knowledge/ontology_only/full` 模板及现有中文普通预置全部由上述 4 套替换，不得继续 seed。

## 9. 参数、UI 与 API 要求

1. 算子参数 schema 继续 `extra=forbid`，范式发布时完成静态校验；
2. UI 只展示本文保留/新增的正式算子；退役算子和研究实体/本体算子均不显示；
3. embedding 编辑器以默认 policy 矩阵 + 用户 override 呈现，不做单一 mode 下拉框；
4. query expansion/summary 明确标记“离线生成式 LLM、实验、失败可降级、增加成本”；

6. Run/Build 摘要分别展示基础资产成功和增强资产 degraded，不能只显示总 SUCCESS；
7. 不提供 GraphRAG/RAPTOR/篇章关系的产品文案或开关。

- 产品面实体/本体/图谱入口。研究代码本身不删。

### 10.2 数据库重置保护

清库脚本必须同时校验：明确的 test/development 环境标识、允许列表中的数据库名/host、显式确认参数；打印解析后的绝对目标和将清理的表，任一校验失败立即退出。不得提供可误用于生产的无保护通用 drop/truncate 命令。

**reset 范围白名单（2026-08-29 审查追加）：**脚本必须显式区分 control-plane（用户、MCP 密钥、开放库配置、域注册——**保留不清**）与 domain 资产库（派生资产、范式版本/绑定/manifest——**清理对象**），两类清单分别打印并逐项确认；越界触碰 control-plane 表即退出。

### 10.3 重建顺序

```text
停止挖掘/检索服务

→ 对全部测试知识库重新挖掘
→ 校验 readiness、引用和配套检索
```

不做旧 manifest 迁移、deprecated 周期、双写、旧链 fallback 或旧 API 兼容。

## 12. 验收标准

### 12.1 单元与契约

- projector 对每种 content type 生成预期 representation，canonical/source refs 可解析；
- table row 保留表头、caption、cell/source span，不再因 compatibility projection 丢类型；
- alias 的 answer span 无法回源时必丢弃；summary 必标 derived；
- embedding policy 优先级、override、provider 不支持、显式 fallback 均有测试；
- persist 任意一步失败不发布半成品 readiness；
- 研究算子和退役算子不出现在正式 catalog/seed/API/UI。

### 12.2 集成/E2E

- 四套挖掘预置均可新建、发布、执行；标准混合为默认；
- LLM 服务不可用时两套基础预置正常，两个实验预置基础资产仍可发布并标 degraded；
- 同源 raw/query alias/summary alias 不在检索端重复占位；
- 真实包含大文档、短碎片、跨页表格、列表、代码、公式、caption 的最小语料可完整重建；
- MCP 能从搜索命中回到准确 KB、文件、章节、页码和原文；structured query 的字段来自真实 schema；
- 授权用户不能通过 opaque ref 读取未开放 KB 或非活动快照。

### 12.3 最小 smoke/eval

不设 P8 正式晋级门槛，但至少记录标准混合相对关键词基线的 Recall/重复率/空结果、引用解析成功率、表格直查正确性和端到端延迟；实验 alias/summary 另记录生成覆盖、无效/污染、成本和降级率。另须记录多表示带来的 embedding 调用/向量量相对旧链路的增量（预计 3-5 倍），确认成本可接受；并显式对比**默认链 vs 问题别名增强链**的中文口语查询命中差——这是零 LLM 默认线唯一的质量赌注。若增强没有实际收益，保持实验非默认，不得以“成功生成资产”宣称有效。
