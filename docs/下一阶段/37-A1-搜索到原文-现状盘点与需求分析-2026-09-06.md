## 0. 核心结论

**位置信息的生产端已经齐全且高质量，34 号 §3.3"已经产生但尚未被消费"经代码核实属实。断点全部在消费链，共三处：**

| 断点 | 内容 | 证据 |
|---|---|---|
| **B1 切片/投影降级为 id 引用** | 切片与检索资产只保留 `element_id + evidence_span_ids` 引用，位置实值（页码/行号/bbox/sheet/cell）不进切片不进投影表；且**全系统不存在任何"span_id → IR 实值"的运行时回读服务**（结构预览 API 只返回 `has_evidence` 布尔） | `segment_compiler/compiler.py:306`（只取 span_id）；`snapshot_store/read_service.py:393` |
| **B2 检索资产无位置列，协议槽位空转** | `asset_retrieval_units_v2` 等七张投影表无任何位置列；serving 的 `EvidenceSource.page` 字段协议里存在但**恒 null**（无数据源）；Java 侧 `JsonUtils.parseSourceRefs` 还在解析早已不写的旧格式 `raw_segment_ids`（漂移死码） | `retrieval_projection/schema.py:17-63`；`EvidenceResponse.java:45-57`；`EvidenceHydrateOperator.java:616-621`（page 硬编码 null）；`JsonUtils.java:21-28` |
| **B3 网页无结构入口 + 双标识体系无桥** | 检索面板来源行是纯文字（不可点击）；挖掘预览面用 `element_id` 体系，serving 用 `doc_/st_` ref 体系，**两套标识无任何互解析通道**——"从搜索结果跳进文档大纲对应位置"当前结构性不可能 | `KbSearchPanel.vue:285-295`；`mining.ts:124-132` vs `TargetRefFormat.java:8-13` |

**最重要的推论：A1 第一批格式（PDF 页、Markdown/文本行范围、Excel Cell）不需要动任何解析器。** 三种格式的位置实值今天就在 Parse IR 里并随快照持久化在 parse bucket（内容寻址、按 `document_snapshot_id` 关联）。A1 全部工作量在"把已有数据接到消费端"，属于通道与消费层工程。

### 1.2 Parse IR 数据模型（位置相关字段）

`contracts/parse_ir/types.py`——位置信息集中在 `EvidenceSpan`（48-70 行），**四通道设计**：

| 通道 | 字段 | 覆盖格式 |
|---|---|---|
| 字符偏移 | `text_range (char_start,char_end)` | 全部（**元素文本内偏移，非全文档偏移**——口径注意） |
| 行号 | `source_locator {line_start,line_end}` | MD/TXT |
| 页面区域 | `visual_region {bbox/polygon, page_index}` | PDF/PPTX |
| 原生坐标 | `native_ref`（sheet+cell A1 / xpath / paragraph_index / page+cell[r,c]） | XLSX/HTML/DOCX/PDF 表格 |

配套：`Container.page_number`（125-148）、`TableCell.row_index/column_index/source_span_id`（155-172）、校验器强制"每个 span 至少带一个 locator"（`parse_ir/schema.py:310-336`）。序列化 round-trip 全字段保留。**IR JSON 持久化在 parse bucket（`v1/{ab}/{cd}/{sha256}` 内容寻址），快照行 `parse_ir_storage_object_id` 指向它（008 SQL:221；`shadow_parse/service.py:420-473`）**——这是 A1 受控重放的数据基础。

### 1.4 双标识体系与结构工作台

- **挖掘预览面**（三栏结构工作台，文档结构图 v2）：数据来自 mining `/api/kb/{kb}/documents/{id}/parse-result`，大纲节点用 `element_id/level/order_index/parent_section_element_id`（`mining.ts:124-132`）；表格预览是截断的 `string[][]` **无行列坐标**（`mining.ts:143-153`）；页面明示"完整表格查询目前可通过 Agent 的 get_knowledge"（`KbDocPreviewView.vue:259-261`）。

## 2. 需求分析

### FR-A1-1 来源记录数据通道（核心）

1. 每条**可返回证据**必须携带来源记录，结构分两级：
   - **L1（必填，全格式）**：document_ref + 章节（面包屑 + 结构节点 ref）——现状已基本满足，补章节 ref 与 element 锚的绑定；
   - **L2/L3（按格式能力声明，声明了才进可解析率分母）**：PDF=页码（+表格页内 cell 行列）；MD/TXT=行号范围；XLSX=**sheet 名**+单元格坐标（A1 或 row/col）；DOCX=表格 table_index+行列（正文仅段落序号，作位置说明不进 L2 分母）；HTML=xpath。
2. 来源记录**以 `document_snapshot_id` 为版本锚点**生成与存储，随 Build membership 生效——满足 34 号"同一篇文档的结构、搜索、来源、表格结果作为不可拆分的文档知识版本生效"。
3. 生成位置在**投影层**（从 IR 物化），不进解析器、不进召回 SQL 热路径；serving 在 hydrate/assemble 阶段按 Top-N 物化进 `EvidenceSource`。
4. 位置不可得时字段缺省并附 `locatability` 说明（对应 P0-8"来源位置不可用"态），**严禁伪造**（无证据问题不得给出伪造来源）。

### FR-A1-2 证据输出来源增强

1. `EvidenceSource` 启用 `page` 并按格式扩展位置字段（行范围/sheet/cell 等，字段集以实施设计定，协议向后兼容：旧客户端忽略新字段）。
2. **每个片段独立来源**：多条 evidence 各自绑定自己的位置，禁止一组来源笼统支持整段（现状 source 结构已按条独立，补内容即可）。
3. 摘要/问题别名命中后，返回的必须是 canonical 证据的位置（复用现有 alias→canonical 水合，透传位置）。
4. 表格证据的 cell 坐标进入输出（现状 rowIndex 只进内部 provenance）。

### FR-A1-3 受控重放（历史数据补齐）

1. 存量文档从 parse bucket 的 IR **重投影**补来源记录——不重新调用解析模型（IR 内容寻址已在），不重新切片。
2. **硬约束（防版本事故）**：重放不得改变 snapshot 指纹、不得使已发放的 ev_/st_/doc_ ref 失效（ref 的 HMAC 编码含 snapshotId）、不得改变当前生效版本的内容语义（只增位置元数据）。
3. 重放产物走与 36 号一致的 staging→final 纪律（或等效的幂等补齐协议），可批量、可断点、可审计。
4. 重放范围以"该快照 IR 中实际存在 locator"为界——IR 里没有的（如 DOCX 页码）不补、不估。

### FR-A1-4 标识桥接（element_id ↔ doc_/st_ ref）

1. 同一 snapshot 下，挖掘预览面的 `element_id` 与 serving 的结构 ref 必须可互解析——这是 P0-6"章节可点击进入大纲对应位置"的结构前提。
2. 桥必须是**投影期固化的数据**（随快照生成），不允许运行时按标题文本猜测匹配（34 号 P0-2 已否决标题文本作身份）。
3. 实现位点（投影存映射列 vs 独立映射表 vs ref 内嵌锚）留实施设计。

### FR-A1-5 网页搜索结果成为结构入口（P0-6）

1. 来源文件名可点击 → 打开文档页（current_serving 视图，复用 A0-1 双视图）。
2. 章节可点击 → 文档页大纲对应位置（依赖 FR-A1-4）。
3. 表格证据显示"查看表格" → 文档页表格详情（该页表格面需补行列坐标展示，现状 `string[][]` 无坐标——最小增量，不做网页自由查询，那是 A3）。
4. "查看完整"语义拆分：「查看更多文本」（现状行为）与「打开原件」（download/preview-url）两个明确入口。
5. 所有跳转链接由服务端在当前权限下解析（机制已有，见 1.5），前端不拼接内部 id。
6. 不支持在线定位的格式（DOCX/PPTX/XLSX 原件）：显示真实位置说明（如"第 N 段/表格 N 第 r 行 c 列"）+ 下载入口；不能高亮就不显示"精确定位"按钮。

### FR-A1-6 网页与 Agent 一致（P0-7）

位置与来源由 serving 同一投影产出，网页与 MCP 消费同一 `EvidenceSource`；前端不得自算位置规则。Agent 工具名不增（get_knowledge 现状满足）。

### 非功能需求

| 项 | 要求 |
|---|---|
| 权限 | 位置/链接解析全程过授权快照集（现有机制）；权限撤销后旧 ref 立即不可用（现有 ref 授权语义） |
| 性能 | 位置物化只在 hydrate/assemble（Top-N）发生，召回 SQL 零改动；对接 34 号"各链路 P50/P95/P99 增幅 ≤15%" |
| 口径 | 字符单位/页码起点（1 基）/坐标口径按 1.2 与 D6 冻结；中文/emoji 场景行号与 A1 坐标不偏移需专项验证（34 号 P0-4 末条） |
| 指标 | 来源可解析率分母=**声明 L2/L3 能力格式的已返回片段**（PDF/MD/TXT/XLSX），DOCX 等不混入分母但必须有原因记录——直接对接 34 号 §7 发布指标 |

## 3. 数据通道方案空间（需求级约束，非详设）

| 方案 | 思路 | 优点 | 风险 |
|---|---|---|---|
