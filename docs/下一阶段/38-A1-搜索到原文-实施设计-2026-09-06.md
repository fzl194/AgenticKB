## 1. 总体架构

在"搜索表示 / 结构化投影 / 原始证据"三面之外新增**来源记录面**（第四面）：

```text
Parse IR（parse bucket，位置实值已在）
   │  ① source_locator 物化（挖掘侧，project 阶段后）
   ▼
asset_source_locators(_staging)          ←—— ② 受控重放 CLI（存量快照幂等回填）
   │  ③ mining_finalize Build 组装事务晋升（复用 36 号纪律）
   ▼
asset_source_locators（final）
   │  ④ serving hydrate/assemble 按 (snapshot_id, representation_id) 批量取
   ▼
EvidenceResponse.source.locator          → MCP（Agent）与网页同源
   │  ⑤ 网页导航解析端点（授权内 ref→导航锚）
   ▼
kb-ui：来源可点击 / 位置徽标 / 打开原件 / 大纲·表格锚点跳转
```

关键不变量：
- **不碰编译器与切片**：CompiledSegment、compiler_fingerprint、snapshot 指纹零改动——既有快照与已发放 ref 全部不受影响（37 号 FR-A1-3 硬约束）。
- **召回热路径零改动**：locator 表只在 hydrate/assemble（Top-N）读取，FTS/dense/RRF/rerank 不感知。
- **协议只增不改**：`EvidenceSource` 新增嵌套 `locator` 对象（NON_NULL 省略），旧客户端无感。

## 2. 数据模型（挖掘侧）

### 2.1 DDL：`databases/asset_core/schemas/014_a1_source_locators.sql`

```sql
CREATE TABLE IF NOT EXISTS asset_source_locators (
    snapshot_id        TEXT NOT NULL,
    representation_id  TEXT NOT NULL,   -- join 键 = asset_retrieval_units_v2.representation_id
    target_ref         TEXT NOT NULL,   -- 冗余：按证据 target 反查（"{doc}#table_row:{t}:{r}" 等）
    document_ref       TEXT NOT NULL,   -- bundle.document_ref（doc_key）
    source_format      TEXT NOT NULL,   -- md|txt|pdf|xlsx|docx|html|pptx|...（可解析率分母口径用）
    locator_kind       TEXT NOT NULL,   -- page|line_range|sheet_cell|native|section_only|unavailable
    section_path       TEXT,            -- L1 章节面包屑（facets 冗余）
    section_element_id TEXT,            -- L1 桥：IR 大纲元素锚（网页跳转用）
    page               INTEGER,         -- PDF 页码（1 基，取元素跨页首页）
    line_start         INTEGER,         -- MD/TXT 行号（0 基 end-exclusive，同 IR 契约）
    line_end           INTEGER,
    sheet              TEXT,            -- XLSX sheet 名
    cell               TEXT,            -- 首列 cell 绝对坐标（"A1"）
    table_ref          TEXT,            -- 表行单元：table_id
    row_index          INTEGER,
    native_ref_json    JSONB,           -- 兜底原生坐标（xpath/paragraph_index/slide_index…）
    description        TEXT,            -- 人读位置说明（DOCX"第N段/表格N第r行"等）
    locator_version    TEXT NOT NULL,
    PRIMARY KEY (snapshot_id, representation_id)
);
-- staging 孪表同构（013 模式）；structured_assets 补列：
ALTER TABLE asset_structured_assets ADD COLUMN IF NOT EXISTS sheet_name TEXT;
ALTER TABLE asset_structured_assets_staging ADD COLUMN IF NOT EXISTS sheet_name TEXT;
```

注册点：
- `infra/pg_schema.py`：`_SOURCE_LOCATORS_DDL` 挂 `_RETRIEVAL_ASSETS_V2_DDL` 之后（启动幂等迁移）。
- `retrieval_projection/schema.py`：契约 statements 追加（内存测试）；`PROMOTE_TABLE_COLUMNS` 追加 `asset_source_locators`（自动纳入 Build 组装晋升）与 `asset_structured_assets` 列清单补 `sheet_name`。

**分母口径落地**：`locator_kind ∈ {page, line_range, sheet_cell}` = 已声明可精确定位的片段（进可解析率分母）；`native/section_only/unavailable` 不进分母但必有行与原因（description / native_ref_json）。

### 2.2 每格式取值规则（locator_kind 判定与字段来源）

按 representation_type 分层：

| representation_type | kind 规则 |
|---|---|
| `segment`（prose 等） | 按 span 实值：PDF→`page`；MD/TXT→`line_range`；XLSX→`sheet_cell`（取首个 cell span）；DOCX→`native`（description="第N段"）；HTML→`native`（xpath）；PPTX→`native`（slide_index）；三通道全空→`unavailable` |
| `table_row` | `sheet_cell`（sheet=TableAsset 容器名；cell=行首列绝对 A1；table_ref/row_index 恒带）；DOCX/HTML 表→`native`（description="表格N 第r行" + native_ref） |
| `table` | 同 table_row（整表粒度，row_index 空） |
| `section` / `document` | `section_only`（L1 即可，34 号"所有片段至少 L1"） |
| `query_alias` / `summary_alias` | **不写行**——别名命中回 canonical 证据（hydrate 按 canonical representation 取 locator） |

聚合规则：单元收集 `source_refs` 的 `evidence_span_ids` → page 取最小页、line 取区间并集（min start / max end）、sheet/cell 取首个非空、native 取首个；跨通道冲突时按 kind 优先级 page > line_range > sheet_cell > native 判型。

`section_element_id`：segment.element_ids → IR 元素树最近 section/heading 祖先（与 `read_service._segment_source_context` 同语义，在 extract 内独立实现并用同一批测试对齐）。

### 2.3 模块：`knowledge_mining/mining/source_locator/`

- `extract.py`（**纯函数**，只依赖 contracts）：`(ParsedDocument, Sequence[CompiledSegment]) -> tuple[LocatorRecord, ...]`。每格式 fixture 单测在此层覆盖（含跨页/多 sheet/中文 emoji 行号）。
- `service.py`：`materialize_for_snapshot(snapshot_id)`——snapshot 行→IR 对象加载（复用 snapshot_store 的 LRU loader 语义）→ units `list_for_snapshot` → extract → staging `replace_for_snapshot`。返回计数与降级原因。
- `repositories_pg.py` / `repositories_memory.py`：replace/list/按快照晋升（`promote_locators(snapshot_ids)`：per-snapshot DELETE final + INSERT SELECT staging + 清 staging，**专用最小晋升，绝不动其他六表**——不得复用 `promote_snapshot_assets`，那会清空 staging 为空的 final 表）。
- `replay.py`：受控重放 CLI。`--domain/--kb/--snapshot/--dry-run`；遍历已 commit 快照（Build membership 视角外存量全量），逐快照物化→staging→`promote_locators` 幂等提交；不动 snapshot 指纹、不发 Build、不失效 ref；输出可审计统计（覆盖/跳过/降级计数）。

### 2.4 handler 接线（不加算子）

`retrieval_unit_project_handler` 成功路径末尾追加 `source_locator_service.materialize_for_snapshot(bundle.snapshot_ref)`：
- 16 算子目录、模板、范式清单零改动；
- 物化异常→**degraded 不阻断**（bundle 计 `locator_ready=false` 事实），与批次8 实验算子失败语义一致；
- `build_new_chain_services` 的 `NewChainServices` 增 `source_locator_service` 字段。

### 2.5 sheet 名补投影（D7）——实施修订

原设计"structured_assets 加 sheet_name 列"已修订：**不加列**。sheet 名落在两处即可满足 A1 消费面：
1. locator 行的 `sheet` 字段（serving 证据 `source.locator.sheet`，Agent 与网页同源）；
2. mining parse-result 的 tables 视图直读 IR 容器树补 `sheet_name`（`read_service._sheet_name_of`，网页表格详情显示）——快照不可变，容器树直读即真相，避免动 structured_assets 表结构与晋升清单。

## 3. serving（Java）

### 3.1 读取

- 新 `SourceLocatorMapper`（XML）：`selectBySnapshotAndRepresentations(snapshotId, representationIds)` → `SourceLocatorRow`；只读 final 表；复用域库数据源。
- `EvidenceHydrateOperator`：每轮 hydrate 对涉及的 rep id 去重后**一次批查**；`build()` 的 `SourceProjection` 增 locator。alias rep 无 locator 行时沿 `canonical_evidence_id` 回源 unit 取（实现时验证 query_expansion 命中链）。

### 3.2 协议（只增不改）

```java
// EvidenceResponse.EvidenceSource 增：
@JsonProperty("locator") EvidenceLocator locator;   // NON_NULL 省略
record EvidenceLocator(String kind, Integer page, Integer lineStart, Integer lineEnd,
                       String sheet, String cell, String tableRef, Integer rowIndex,
                       String description) {}
```

`HydratedEvidence.SourceProjection` 平行增字段；`AssembleOperator.toItem` 投影。`page` 旧字段保留（与 locator.page 同值，向后兼容）。

### 3.3 网页导航解析端点（P0-6"服务端解析"）

`GET /api/v1/evidence/{ref}/source`（鉴权同 `/api/v1/evidence`：X-KB-User + kbId → 授权快照集内解析）：

```json
{ "document_id": "…", "section_element_id": "…", "section_path": "…",
  "table_ref": "…", "row_index": 3, "locator": { …同上… } }
```

document_id 由 snapshot_id 经 `asset_build_document_snapshots` 反查（target_ref 的 `{doc}` 段是 doc_key 非 UUID，不能直接当路由参数——实现时以 DB 反查为准）。越权/不存在同一响应（404 kb_not_found 语义，沿用现有 handler 分支）。

### 3.4 死码清理（D2）

删 `JsonUtils.parseSourceRefs/parseTargetRef` 的 `raw_segment_ids` 旧格式分支及其测试（确无调用方后整段删除）。
