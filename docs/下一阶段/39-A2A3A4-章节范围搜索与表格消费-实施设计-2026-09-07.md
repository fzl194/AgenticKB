## 1. 批次一：1.0.2 权限修复

### 1.1 serving admin 全通

`KnowledgeBaseMapper.xml selectAccessibleKbIds` 的 OR 组追加一支：

```sql
OR u.site_role = 'admin'
```

（`u` 已按 `username + status='active'` JOIN；NULL 安全。语义与 mining `list_visible_kb_ids` 对齐：站点管理员可读域内全部 **active** 库；软删/跨域仍不可见。）MCP 用户密钥走同一 `X-KB-User` 判定，自动一致。

### 1.2 前端错误分型

`localizeSearchError` 按响应体 error code 分型（`kb_not_found` / `no_active_kb_build` 解析自 body JSON 的 `error` 字段，正则兜底）：

- `kb_not_found` → 「无法访问所选知识库：库不存在，或当前账号无读取权限（需库主/成员/public/站点管理员）」
- `no_active_kb_build` → 「所选知识库暂无可检索内容：尚未完成挖掘，或全部文档挖掘失败」
- 401/403 → 权限提示（不变）

防探测语义不动：无权限与不存在仍同码 `kb_not_found`（404）。

### 1.3 测试

- Java IT（KbAccessServiceIT 扩矩阵）：site_admin 读他人 private ✅；admin 软删库 ❌；admin 跨域 ❌；owner/editor/viewer 成员读 private ✅；non-member private ❌ public ✅；匿名 public ✅。
- 前端 vitest：三分型文案 + 未知错误原样。

## 2. A2：章节导航与范围搜索

### 2.1 数据（挖掘侧，015 DDL）

```sql
ALTER TABLE asset_structure_nodes ADD COLUMN IF NOT EXISTS element_id TEXT;      -- 大纲锚桥（A1 FR-A1-4 收口）
ALTER TABLE asset_retrieval_units_v2 ADD COLUMN IF NOT EXISTS section_ref TEXT;  -- 章节归属物理列
CREATE INDEX IF NOT EXISTS idx_aru_v2_section ON asset_retrieval_units_v2(snapshot_id, section_ref);
--（staging 孪表同步 ALTER）
```

- **section 稳定身份**：section 节点 ref 由 `#section:{标题路径}` 改为 `#section:{序号路径}/{标题}`（序号路径=各级同级序号，如 `0/2`）。同级同名标题不再碰撞；标题保留于人读与 title 列。仅影响**新快照**（旧快照 final 行不动，旧 st_ ref 照常解析）。投影端（structure_projection）与 serving 端（TargetRefFormat 注释、StructureRefService 候选枚举）同步认知。
- **section ordinal**：同级顺序 = IR 元素 order_index 序。section 节点写 ordinal（现在仅 segment 有）；prev/next 从「无序返回空」变为真实可用。
- **units.section_ref**：非 section 单元写其所属 section 节点 ref（projector 已算 section 链）；document 级 NULL；alias 继承源单元值。section 单元写自身 ref。
- **element_id 桥**：structure_projection 产 section 节点时写最近大纲元素 id（IR 侧 order 定位；与 A1 locator `section_element_id` 同源同语义）——大纲节点 ↔ st_ ref 从此可互解析。
- 晋升面：PROMOTE_TABLE_COLUMNS 两表列清单同步追加。

### 2.2 范围下推（serving）

- 协议：`within` 白名单增 `section_scope`（值 `exact|descendants`，缺省 exact——向后兼容，现网调用零变化）。
- 下推 SQL（FTS/dense 共用同一片段 `unitPushdownFilters`）：
  - exact：`AND section_ref IN (...)`（section 单元自身含在 section_ref 内，命中章节摘要与正文一致）；
  - descendants：内嵌有界递归 CTE（`asset_structure_nodes.parent_ref` 沿同快照集展开）→ `section_ref IN (SELECT ref FROM closure)`。**不做应用层 IN-list**（33号 G3 禁令）。
- 守卫：roots ≤64、每 root 后代 ≤512，超限 400 `section_scope_too_broad`（不退化为宽搜索）。
- 越界率=0 的保证点：约束在召回 SQL（FTS 与 dense 同一 predicate），hydrate/assemble 只做既定扩展（命中小段仍带范围外父上下文属 P0-3 明确允许的「可展开父章节」，评测以**命中小段**计越界）。
- `document_refs` 语义不变。

### 2.3 导航公共 REST（33号「同 service」要求）

```
GET /api/v1/structure/{ref}/navigate?relation=&depth=&limit=&cursor=&domain=&kbId=
GET /api/v1/structure/{ref}/inspect?domain=&kbId=
POST /api/v1/structure/{ref}/query            ← A3（§3.4）
```

用户头 `X-KB-User` + kbId → `KbAccessService` 实时授权 → **同一** `StructureNavigateService`/`InspectService`/`StructuredQueryService`（MCP internal 路径零复制）。ref 解析沿用 StructureRefService（越权/不存在同响应）。

### 2.4 网页

- **KbDocPreviewView**：大纲节点可点击（选中态）；选中后操作条：父章节/子章节/上一节/下一节（走 navigate REST）、「本节搜索」「本节及子节搜索」（携带 scope 跳检索面板）。
- **KbSearchPanel**：scope 状态区（范围徽标：整篇/本节/本节及子节 + 章节名），可清除；检索请求带 `within: {document_refs?, section_refs?, section_scope?}`。
- **从搜索进入结构保留范围**：证据卡「查看结构」→ 文档页带 scope query；文档页「继续搜索」→ 面板回填 scope。
- **MCP**：`within` 已整体透传（mcp_server/client.py:332）；仅更新 schemas.py 注释为真实语义，不加工具。

### 2.5 A2 测试

## 3. A3：表格精确消费

### 3.1 数据（挖掘侧，015 DDL 续）

```sql
ALTER TABLE asset_table_cells ADD COLUMN IF NOT EXISTS value_type TEXT;       -- number|text|date|empty（IR 事实）
ALTER TABLE asset_table_cells ADD COLUMN IF NOT EXISTS normalized_value TEXT;
ALTER TABLE asset_table_cells ADD COLUMN IF NOT EXISTS formula TEXT;
ALTER TABLE asset_table_cells ADD COLUMN IF NOT EXISTS row_span INTEGER;
ALTER TABLE asset_table_cells ADD COLUMN IF NOT EXISTS column_span INTEGER;
ALTER TABLE asset_table_cells ADD COLUMN IF NOT EXISTS source_span_id TEXT;
ALTER TABLE asset_structured_assets ADD COLUMN IF NOT EXISTS sheet_name TEXT;
--（staging 孪表 + PROMOTE 列清单同步）
```

- 投影端：compiler 的 row_cells 三元组扩展为携带全部 cell 事实（或并列新 metadata 键），structure_projection 落列；legacy 三元组回退为 NULL 列（兼容旧 workflow 重放）。
- **历史补齐**：`python -m knowledge_mining.mining.table_assets.replay`——按快照从 IR TableAsset 回填缺失列（`WHERE value_type IS NULL` 幂等 UPDATE；sheet_name 从容器树补 structured_assets）。不动指纹、不发 Build、不失效 ref（同 A1 重放纪律）。

### 3.2 serving 类型系统（date 补齐）

- `schemaOf`：列类型优先取 `value_type` 列的真实声明（全列一致 number/date → 该型；混合或全空 → 现有值扫描回退，legacy 行为不变）。
- pivot SQL 增并列聚合 `jsonb_object_agg(column_name, COALESCE(normalized_value, value))` 作为比较基（数值/日期比较走规范化值；无规范化值回退 raw）。
- date 谓词：`::date`/`::timestamp` 比较（不可解析 → type_mismatch 可修正错误，禁止静默退化文本匹配）。
- 错误面不变：unknown_field/type_mismatch/unsupported_operation/result_too_large 全部保留，**查询失败不回退模糊搜索**。

### 3.3 REST + 网页

- `POST /api/v1/structure/{ref}/query`（§2.3 同 controller），body=QuerySpec JSON，parseSpec 同一校验。
- **KbDocPreviewView 表格 tab 升级**：表格卡片增「精确查询」——展开查询面板（TbTableQueryPanel.vue）：
  - schema 驱动（inspect 或 query 响应内嵌列+类型）：选列复选、筛选行（字段/操作符/值，按类型给输入）、排序、分页（cursor）、聚合条（count/sum/avg/min/max，仅数值列）；
  - typed error → 可修正提示（字段不存在/类型不符/结果过大各给文案与下一步）；
  - 结果行「回表格」：row_index → 预览行高亮 + `查看来源`（复用 A1 `/source` locator：sheet!cell/table_ref/row_index）。
- 网页与 Agent 一致性：同一 service 同一 SQL，E2E 断言 REST 与 MCP `get_knowledge(ref, query=…)` 同 spec 同结果。
