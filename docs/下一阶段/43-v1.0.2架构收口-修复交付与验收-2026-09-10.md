## 1. 用户能看到的变化

| 操作 | 修复后行为 |
|---|---|
| 移动新上传文件、改名/移动目录 | 只改数据库逻辑位置，不再尝试搬动不存在的本地原文件 |
| 文件改名、目录整理后重新上传 | 文档 ID/key 保持稳定，按实际目录与展示名称查重；旧位置可创建新的文档身份 |
| 查看来源版本 | 共享快照的文档分别返回自己的来源对象与修订信息 |
| 删除文档后查看总览 | 当前知识统计和搜索都排除该软删文档；管理列表仍可按原规则展示其他未就绪文档 |
| 对同一原文换切片策略 | 正式流程生成独立编译快照；失败不覆盖原有切片，成功后由 Build 选择新结果 |
| 替换当前文件 | 写者可在文件菜单明确选择替换，保留文档名、位置和已可搜索知识；随后手动发起挖掘 |
| 替换后尚未完成挖掘 | 根据后端真实 `knowledge_outdated` 显示“待更新（旧知识可用）”；不覆盖处理中/失败等任务状态 |
| 结构引用读取遇数据库故障 | 返回可重试的 503，不再伪装成“无权限/不存在” |
| 下载或预览原件 | 明确标为最新原文件，与当前可搜索知识和证据来源版本区分 |

## 2. 实现要点

### 文件身份与事务

- `kb/location_repository.py` 集中逻辑目录事务。目录/文件整理不修改对象、内容 hash、revision 或稳定 key。
- 同 KB 的位置更改、创建、复活、改名遵守同一锁顺序与位置查重规则，冲突或子树调整失败整体回滚。
- `folder_id` 与 `directory_path` 在上传、移动、目录整理、复活和恢复时同步维护。
- 上传先按展示位置查重；若某个旧位置产生的 key 仍被已移动文档持有，为新文档生成独立 key。
- 恢复/改名位置冲突返回可解释的 409，不产生内部错误或静默覆盖。

### 来源与统计

- `get_current_serving_snapshot` 的来源关联增加 document_id 约束。
- `_CURRENT_SNAPSHOT_CTE` 增加文档归属与软删过滤，保持“先取最新 selection 再过滤 active”的规则。
- 不把管理文件全集与当前可搜索子集强行设为同一集合。

### 快照隔离

- 解析门面保留原始 FrozenInput；bundle 将其交给编译协调器。
- 正式组合根复用 `SnapshotRecompileService`，为编译指纹创建/复用相应快照。
- 编译结果的 snapshot_id 更新 bundle，持久化与 run document 绑定使用该新 ID。
- 编译继续校验最初冻结的来源，避免处理期间文件已替换却把旧 IR 绑定到新原件。
- raw 内容中的 document_key 使用 snapshot ID，保持共享资产中性。

**边界：** 本次隔离切片策略；embedding/LLM 增强参数变更对应的派生表示身份不在此次全面重建。低层编译器仍有替换语义，正式生产组合根已采用隔离协调器。尚未验证真实 PG 上的并发读窗口。

### 文件替换合同

```text
POST /api/kb/{kb_id}/documents/{document_id}/content
multipart: file + expected_revision
成功: KbDocument
冲突: 409
大小超限: 413
非法格式: 400
字段校验失败: 422
无权/不存在: 遵循既有 KB 错误映射
```

- 路径 KB 与文档所属 KB 显式匹配，写权限在存储前和存储后检查。
- 替换保持原名，要求相同扩展名；MIME 依据保留的文件名确定。
- 限制上传大小并分块处理，复用既有对象存储入口。
- 提交采用 revision 与上传开始时名称的比较更新；上传期间改名、替换、删除时返回冲突。
- 同名重传复活同时固定预期 KB、目录和文件名；并发目录变动不把上传重定向到新位置。
- 新对象与旧对象按内容寻址复用，不为替换新增历史版本管理表，不自动触发挖掘。

## 5. 后续验收入口

1. 对象上传 → 文件移动 → 父目录改名 → 下载 → 挖掘 → 结构/来源读取。
2. 两篇共享快照文档，各自显示来源；删除一篇，当前统计与搜索正确变化。
3. 切片策略变更期间持续读旧知识，失败保持旧结果，成功切换。
4. 替换当前文件 → 跨页面刷新显示待更新 → 挖掘失败仍可读旧知识 → 成功后待更新消失。
5. 并发上传、改名、目录移动、替换和恢复冲突均显式失败，不发生静默覆盖或位置重定向。
