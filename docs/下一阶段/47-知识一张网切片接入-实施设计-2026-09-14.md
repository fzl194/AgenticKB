## 一、需求与定位

### 1. 业务目标

把产业知识的主要来源从人工逐份上传，转为从知识一张网按需、章节级选择性获取产品文档切片；接入后的资料参与底座完整加工消费链路（检索、章节导航、表格查询、MCP），产出全局一份、多知识库复用，并支持上游版本变化的可追溯重同步。

### 2. 已冻结的核心决策（与用户逐项确认）

| # | 决策点 | 结论 |
|---|---|---|
| D1 | 接入形态 | 一张网切片视为**上游解析结果**，构造 Parse IR 进入现有主链；不模拟文件重新解析，不做旁路证据集合 |
| D2 | 切片再加工 | 一张网切片粒度细（按章节/表格），必须经 `segment_compiler` 按我方策略重新汇总成检索切片 |
| D3 | 文档粒度 | 按还原规则把切片子树还原为 **HTML 文件级 Document**（相对规则 β，见四-2），不按绝对层级拆分 |
| D4 | 顺序保证 | `part_id` 全局阅读序：文件内切片升序拼接、文件间按 min(part_id) 排序 |
| D5 | 三层模型 | 管理员地图/产出（离线）→ 域内公共库（产出一次）→ 业务库引用（只读复用） |
| D6 | 复用机制 | `kb_document_refs` 引用表 + 范围 UNION；Document 单归属不动；挖掘只发生一次 |
| D7 | 域约束 | 引用不跨域；每域自建公共库；跨域场景直接重做一遍 |
| D8 | 同步 | 订阅记录持久化勾选范围；手动重同步 + nid diff + 文档级传播；自动定时增量留后续 |
| D9 | 触发形态 | KB 内入口 + 管理员导入页面；凭据走服务端配置 |
| D10 | 字段利用 | 原始全字段 JSONL 存证 + 配置化版本化映射 + 校验拦截（见七） |

### 3. 明确不做（本期）

- 自动定时增量同步（本期手动重同步触发）；
- 跨域引用（重做解决）；
- 切片级密级（public_level）消费侧拦截（一期仅 metadata 继承展示）；
- 全库枚举与非产品文档类型接入（无 aggs/scroll，协议上不可行）；
- MCP 通道的一张网操作（仅网页管理面）。

## 二、总体架构

```text
┌─────────────────── 管理员（域内）───────────────────┐
│  一张网导入向导（新增管理员页面）                      │
│  多字段查询 → 摸底 → 章节树预览 → 确认导入（逐文档）    │
└──────────────┬────────────────────────────────────┘
               ▼ 异步导入任务
┌─────────────────── 全局资产层 ──────────────────────┐
│ 域公共库「一张网产品文档」（每域自动建，普通 KB）        │
│  source_id 包 → KB 目录树（path 上层）                │
│  β 规则还原的 HTML 文件 → Document（逻辑文档标记）     │
│  → 挖掘一次：对象→IR→Snapshot→切片/结构/摘要/向量→Build │
│  + onenet_imports 导入记录（订阅：范围/游标/版本）     │
└──────────────┬────────────────────────────────────┘
               ▼ 引用（不拷贝字节、不重挖）
┌─────────────────── KB 消费层 ───────────────────────┐
│ 业务 KB「从一张网引用」：浏览已导入文档的章节目录树     │
│ → 勾选子树/文件 → 一键批量引用（kb_document_refs）    │
│ → 本库检索/章节导航/表格查询/MCP 立即可用             │
└─────────────────────────────────────────────────────┘
```

### 关键机制：切片批次即文件格式

Document 的 MinIO 对象 = 该文件的上游切片**全字段 JSONL 原文**。挖掘管线注册 parse adapter `onenet_jsonl`，把 JSONL「解析」为 Parse IR。由此：

- 挖掘 Run 管线结构（对象→FrozenInput→解析→IR→Snapshot→切片编译→投影→Build）**不改**，onenet 文档与 pdf/docx 走同一条流水线；注册与参数有两处必要改动（见下）；
- 原始证据完美存档，上游字段演进永不丢数据（详见七）；
- JSONL 是重同步 nid diff 的本地依据。

**adapter 注册与路由**（实施必改点，不留模糊）：

- 对象写入时强制设置专用 MIME `application/x-onenet+jsonl`（import_service 写 `asset_storage_objects.mime`，`_kb_object_documents` 冻结的就是它）；
- `parse_adapters/registry.py` 注册 `onenet_jsonl` descriptor 声明支持该 MIME（**必须**先于 legacy_txt 等文本类 descriptor，因 registry 按首个 MIME 命中胜出——专用 MIME 保证不被抢路由）；
- `parse_adapters/factory.py` 配对 normalizer；
- `workflow/operators/options.py` 给 `hierarchical_summary_generate` 增加「摘要深度上限」参数（深树前 N 层仅作 structural context）。

即：管线结构不改，注册/配置面有上述四处显式改动。

## 三、一张网接口事实（实测，实施必须遵守）

来源：`kone_connector/docs/01_api_protocol.md`。

| # | 事实 | 对实施的影响 |
|---|---|---|
| 1 | 接口 `POST /api/search/source_type?source_type=0`；token 动态换取（appid 凭据），过期返 400/401 | client 自动重取 token 重试一次 |
| 2 | 单查询上限 10000（from+size）；无 aggs/scroll/PIT | 分段拉取必带 sort；目录枚举不可行 |
| 3 | `track_total_hits:true` 才有真实 total（默认封顶 10000） | 摸底/校验一律带 track_total_hits |
| 4 | 无稳定排序 from 翻页会重复/遗漏 | 段内翻页必须 `sort part_id asc, nid.keyword asc` |
| 5 | 大文档 part_id 全局唯一连续 1..N（N==total） | range 分段拉取 + 断点续传 + 完整性校验 |
| 6 | `nid` 切片全局主键；`path` 即章节树（` > ` 分隔，10+ 层）；`title` 恒等于 `path[-1]` | 主键与结构映射依据 |
| 7 | 表格在 content 的 `[tbl_predict_start/end]` 块内（管道表格） | table 元素抽取 |
| 8 | 同一 source_id 会随 `parsed_version` 重新解析 | 重同步版本探测信号 |
| 9 | `url` 为包级（同 source 所有切片相同），不能区分原始 HTML 文件 | 文件边界只能从 path 树推断（见四-2） |
| 10 | fuzzy 查询命中封顶 10000；多条件 AND | 管理员查询页按 source_id 去重展示 |

### 2. 还原规则 β（文档粒度与顺序）

实测确认：path 树即 HWICS/CHM 包的 TOC 文件树，每个节点都可能是一个 HTML 页面；节点可既有直属切片又有子节点（h1 正文 + h2 小节）；绝对层级不可靠（分支高度不齐、语义错位）。

```text
规则 β（默认，rule_version 版本化，参数可调）：
  文件 = path[-2] 节点（页面），path[-1] 为文件内直属标题
  文件内容 = path[-2] 节点直属切片 + 其下一层小节切片，按 part_id 升序拼接
规则 α（兜底）：
  叶子节点自身有切片且无更深层 → 自身即一个文件
边界归并：
  更深层标题（path 落在标题而非文件上）向上归并到最近的有直属切片的祖先
```

- 文件内顺序：切片 part_id 升序（实测同 path 多切片 part_id 连续）；
- 文件间顺序：每文件取切片 min(part_id) 排序 = TOC 阅读序；
- 目录树：文件之上的 path 层级映射为公共库 kb_folders；
- 规则校准：UDG 全量数据（DOC1101733708，157,866 切片）内网验证；规则不对调参数不改正代码。

### 3. IR 映射（ir_builder）

| 一张网 | Parse IR |
|---|---|
| path 各层级（剔除包名首段） | heading 元素（level=层级深度），构成标题树 |
| 切片 content（剥离 `[tbl_predict_*]` 标记） | paragraph 元素 |
| `[tbl_predict_start/end]` 管道表格块 | table 元素 |
| part_id | order_index / 阅读序关系 |
| nid | 元素溯源键（provenance，回源与 diff 用） |
| url/密级/版本等 | element/document metadata |

下游自动继承（零新算子）：`segment_compiler` 多段落汇总切片（D2）；`hierarchical_summary_generate` 标题树自底向上摘要（深树加摘要深度上限参数，前 N 层仅作 structural context）；`query_expansion_generate` 问题别名；A2 章节锚点/范围搜索；A3 表格查询；结构图。

### 4. 数据表（新增两张，现有表零改动）

```sql
-- asset_core 库
CREATE TABLE onenet_imports (
    id                     TEXT PRIMARY KEY,
    domain                 TEXT NOT NULL,
    source_id              TEXT NOT NULL,
    doc_name               TEXT,
    parsed_version_seen    TEXT,
    total_slices           BIGINT,
    fetched_max_part_id    BIGINT,
    selection              JSONB NOT NULL,   -- 勾选范围(path 子树) + rule_version + mapping_version
    status                 TEXT NOT NULL,    -- queued/fetching/restoring/importing/mining/done/failed
    kb_id                  TEXT NOT NULL,    -- 域公共库
    folder_root_id         TEXT,             -- 本包在公共库的目录根
    document_count         INTEGER,
    error                  TEXT,
    created_by             TEXT NOT NULL,
    created_at / updated_at TEXT NOT NULL,
    UNIQUE (domain, source_id)               -- 同 source 重复导入拒绝，走重同步
);

-- kb 库
CREATE TABLE kb_document_refs (
    kb_id       TEXT NOT NULL,
    document_id TEXT NOT NULL,
    created_by  TEXT NOT NULL,
    created_at  TEXT NOT NULL,
    PRIMARY KEY (kb_id, document_id)
);
-- document 必须属同域公共库（refs_service 服务端强制校验，不依赖前端）；
-- 引用即只读授权

-- toc 预览缓存（预览发生在导入记录创建之前，独立落缓存）
CREATE TABLE onenet_toc_cache (
    source_id              TEXT NOT NULL,
    domain                 TEXT NOT NULL,
    parsed_version_seen    TEXT,
    toc_json               JSONB NOT NULL,   -- 树 + 每节点切片数 + β 预计文件数
    scanned_at             TEXT NOT NULL,
    PRIMARY KEY (domain, source_id)
);
```

**公共库 bootstrap 与可见性**：

- 公共库 `visibility='private'`、owner=系统管理员账号、`metadata_json.kind='onenet'`；固定名「一张网产品文档」——`knowledge_bases` 现有 `UNIQUE(domain, name)` 即 bootstrap 幂等守卫（upsert on conflict do nothing），并发首建不产生双库；
- `list_visible_kb_ids` / `list_visible` 排除 `kind='onenet` 库（普通用户 KB 列表不可见，只有引用入口间接消费）；
- 引用授权走 refs 分支（document 粒度，见四-5），不依赖公共库本身可见。

**Document 幂等与失败重试**：

- `document_key = onenet:{source_id}:{path 稳定哈希}`（β 还原的文件 path 唯一定位）；重试按 key upsert——已建 Document 复用，不重复建行、不撞 `uq(kb_id, document_key)`；
- 导入中途失败：已建 Document 留在公共库（未完成态），`status=failed` 给真实原因；修复重跑按段文件 + document_key 双层幂等续传；
- 引用入口只认 `status=done` 的导入记录，failed 期间公共库不完整文档不会被引用。

**引用行生命周期与缓存失效**：

- 重同步中消失 nid 的 Document 软删时，**同步删除其全部 kb_document_refs 行**（导入任务负责）；restore 复活该文档时引用不自动恢复（需重新引用）——语义写明，不留隐式行为；
- 引用建立/取消后，涉事 KB 的语义缓存（`ActiveScope.kbScopeKey` 分区）主动失效——kbScopeKey 仅由 KB 集合组成，不随 refs 变化，必须显式失效。

### 5. 范围 UNION（引用生效的核心改造）

「KB→文档集合」解析点按**三类口径**分别处理，收敛为 SQL 视图 `v_kb_active_documents`（自有 ∪ 引用）：

**检索/证据/结构口径（吃引用，UNION）**：

| 接缝 | 位置 |
|---|---|
| Java 检索范围 | `AssetRepository.resolveKbScope`（selectLatestKbSnapshots） |
| Java 结构消费 | `StructureRefService` + `StructureToolMapper` 的 snapshot/document 集合 |
| Java 证据读取 | `EvidenceSourceV2Mapper` 的快照范围 |
| Python 知识读取 | `KbDB._CURRENT_SNAPSHOT_CTE` / `get_current_serving_snapshot` |
| MCP get_knowledge | 复用以上两层，自动继承 |

**管理口径（部分吃引用，分开展示）**：

| 接缝 | 处理 |
|---|---|
| `list_documents_in_kb`（kb/db.py:1428，文件管理器与 MCP list-documents 共用） | 拆两个查询：自有文档（现状不动）+ 引用文档（refs JOIN，只读区）；MCP list-documents 返回合并结果并带 `referenced=true` 标记 |
| 文档可见性 `is_visible` / Java `authorize` | 加「通过本库引用」分支：**document 粒度**——`EXISTS(kb_document_refs WHERE kb_id 可见 AND document_id=目标)` 即只读放行 |
| 文档级操作（下载/预览/元数据） | 引用文档只读放行；移动/改名/删除/替换/重挖一律拒绝（403 + 提示走公共库管理） |

**统计口径（不吃引用，分开命名——吸取 42 号 O4 教训）**：

| 接缝 | 处理 |
|---|---|
| `overview_status_counts`（首页文档计数） | 保持自有口径；引用计数单独字段（`referenced_count`），命名区分 |
| `stats_assets` / 检索类型统计 | 保持自有口径；引用资产是否计入为产品决策，一期**不计入**（避免与物理资产去重指标混用） |

实施时先做一次 `kb_id` 接缝全量审计（kb/db.py 内约 26 处 `d.kb_id`/`kb_id = ANY` 点 + Java mapper XML），按本表三类口径逐点标注「视图化 / 拆分 / 豁免」，审计表进 PR 描述。

**保持不动**：`_kb_object_documents`（挖掘枚举 owned-only——业务库挖掘永不碰引用文档）；`uq(kb_id, document_key)`；单写者不变式；挖掘串行队列。

### 6. 导入流程（管理员，逐文档）

```text
1. 多字段查询  doc_name/file_name fuzzy + doc_type/language 精确（原生 searchQueryList）
              → 按 source_id 去重 → 文档列表（名称/类型/发布时间/版本/产品树 pbi）
              ※ 页面明示「结果可能不全（单查询命中封顶 10000），只作发现手段」
2. 摸底确认    选中 source_id → probe（track_total_hits 真实总数 / part 范围 / parsed_version）
3. 章节树预览  toc_scan（轻量三字段）→ 树 + 每节点切片数
              → 缓存于 onenet_toc_cache（parsed_version 匹配才复用，预览后放弃导入不浪费）
              → 默认整包，可勾子树；显示 β 还原预计文件数
4. 确认导入    异步任务：
              分段拉取（段文件幂等断点，sort 稳定，温和服务限速）
              → 完整性校验（nid 去重 / part_id 覆盖 / path 可挂树 / 表格块配对）
              → β 还原为文件 → 每文件全字段 JSONL 写 MinIO 对象（专用 MIME）
              → 公共库建 Document（key=onenet:{source_id}:{path哈希}，metadata: source_system=onenet,
                logical=true, 全字段映射）+ 目录树 → 入挖掘队列（与手动上传同工作流）
5. 结果查看    导入记录页：状态机/文档数/切片数/失败原因/重试
```

**勾选范围追加**：一期允许管理员在导入记录上**编辑 selection**（合并新增子树），保存后走重同步按新 selection 重放——新子树文档按 document_key 增量补建；不新建第二条同 source 导入记录（`UNIQUE(domain, source_id)` 守卫）。

幂等与失败语义：段文件存在即跳过（demo 机制）；同 source_id 重复导入 409（走重同步）；校验不过=failed 给真实原因，可修复后重跑（已拉段保留）；单文档失败不影响其他。

### 7. 重同步（记录上手动触发）

```text
探测（parsed_version / total / part max 三信号）→ 无变化即完成
→ 有变化：重放 selections 重拉勾选范围
→ nid 集合 diff（新增/消失/更新）
→ 通过 import.document 映射定位受影响 Document
→ 重挖（Snapshot/Build 隔离，失败保旧知识）→ 消失 nid 文档软删
→ 引用方自动收窄（快照选择排除软删）——天然失效传播
```

### 8. 引用流程（KB 内）

```text

```

## 十、风险与开放项

## 十一、原型验证修订（V1.2，2026-09-14）

`onenet_query/` 原型（单文件 FastAPI）内网实测后，用户视角的需求修订如下，主项目按此改造：

### 1. 第一步 · 查询发现（替换 §四-6 步骤 1 的固定四字段）

- **三元组条件构造器**：每条条件 = `{字段, 精确/模糊, 内容}`，可累加多条（AND）；
  字段白名单 12 个（用户定义）：`source_id / nid / url / title / path / content /
  source_site / file_name / category_path / doc_name / doc_type / part_id`；
  字段下拉**中英双语**展示（如「文档名称 doc_name」）
- `part_id` 数字字段强制精确（模糊分词无意义，前端锁定）
- **默认预置条件**：`来源站点 source_site 精确 = support`（产品文档主阵地，可删）+
  `文档名称 doc_name 精确`（空待填）
- 调用走**原生 searchQueryList**（与 DSL 语义一致，协议实证）；翻页拉满
  from+size≤10000 + **nid 去重守卫**（单键 sortField 翻页重复兜底）
- **汇总**：按 source_id 聚合为文档行（文档级字段取首条命中切片）+ 命中切片数 +
  命中章节样例（前 3 个切片标题）；**文档列表分页**（20/50/100）
- 命中 ≥10000 封顶如实提示（黄字）

### 2. 第二步 · 进入文档（章节树必须懒展开）

- 章节树**默认折叠、层层点开**——大文档 5000+ 节点默认全展开会卡死浏览器（原型实测教训）
- 轻量三字段扫描（已有 toc_scan）即可同时产出**β 文件清单预览**：
  restore_files 只依赖 path/part_id（不需要 content），轻扫数据即可算出
  文件划分（file_path/标题/切片数/part 范围/目录）——导入单位预览无需先全量拉取
- 勾选语义不变（勾父节点 = 整个子树，Selection 前缀）；全量获取仍在导入任务内异步执行

### 3. 主项目改造对应关系

| 原型模块 | 主项目落点 |
|---|---|
| 三元组构造器 + 汇总分页 | `probe.search_documents` 重写（透传 + 文档分页）+ 路由/前端表单 |
| 懒展开树 + 文件预览 | `toc_scan` 响应附 `files`；`OnenetAdminView` 去掉 default-expand-all |
| 勾选 → 入库 | 已有（startImport → fetch_selection → β 还原 → 公共库 → 挖掘管线） |

## 十二、落位与向导修订（V1.3，2026-09-15）

内网实测反馈三问题：跨产品文档同名章节在公共库目录树混层、重复导入不同目录
（先命令目录后特性目录）在前端是断头路（409）、文件清单千级行全量渲染卡死。

### 1. 落位规则：顶层 = 文档名 [source_id]

- β 还原剔包名后目录树缺文档级分区，产品文档章节名高度趋同（01 产品介绍/
  02 特性配置…），跨文档必然混层
- **V1.3 落位**：`directory = {doc_name} [{source_id}] / 章节目录链`——
  `restore.top_folder_segment(doc_name, source_id)`；doc_name 缺失退化为纯
  source_id；document_key 哈希锚不变（file_path 保持上游原样，幂等不受影响）
- **目录段清洗**：`restore.sanitize_folder_segment`（分隔符/Windows 非法/控制符
  → `_`，120 字符截断）——章节名带 `/` 不再长出假层级、带 `\`/换行不再炸导入
- toc 轻扫的文件预览 `folder_path` 带同款顶层段（TOC_FIELDS 增加 doc_name）：
  向导看到的目录 = 将来落库的目录；**树路径不带顶层段**（selection 匹配键
  保持剔包名上游段）
- 已按旧规则导入的数据不做迁移——内网验证期数据建议删除重导

### 2. 从记录继续（打通重复导入）

- 一个 domain+source 仍只允许一条导入记录（409 守卫保留）——追加范围的正规
  路径显性化：导入记录行新增「继续勾选」→ 拉缓存树 + **回显当前 selection**
  （setCheckedKeys）→ 勾新章节 → PATCH selection（服务端 union 合并）→
  重同步（新文件经 register_file 走同款落位，自动增量挖掘）
- KB 目录树按 path 驱动累积生长：先 A 后 B、先 B 后 A 落位一致

### 3. 文件清单分页（防卡死）

- 向导 ③ 右侧 β 文件表改前端分页（50/100/200）——千级行全量渲染是 ②③
  卡死的主因；树维持默认只展开根层
- 首次轻扫为分钟级网络等待（非卡死），按钮旁加预期提示；扫描结果落
  `onenet_toc_cache`，重进秒回
