## 一、背景与问题

### 问题 1（Bug）：标题含 `>` 导致文件错分

一张网切片的 `path`（章节目录）是 ` > ` 连接的字符串，β 规则还原文件时
按 `>` 切段后取「倒数第二段节点 = 文件、末段 = 文件内直属标题」。
当标题本身含 `>`（如 `告警 > 处理建议`）时，path 尾部被多切出假段：

| | 现在（错） | 应该是 |
|---|---|---|
| 文件 | `… > 接口管理 > 告警`（假文件） | `… > 接口管理` |
| 标题 | `处理建议` | `告警 > 处理建议`（一个标题） |

连锁影响：文件清单多假文件、章节树多假层级、真文件内容被切走、
挖掘标题链（onenet_jsonl 适配器）层级错误。

### 问题 2（体验）：第三步左右不联动

导入向导第三步左侧章节树负责勾选范围，右侧「β 文件清单」是全量分页
展示——勾选对右侧无任何影响，用户无法预知「勾了这章会导入哪些文件」。

## 三、已对齐的决策（2026-09-20）

1. **修复范围 = 全链路**：文件分组、章节树、挖掘标题链统一用 title 校准
   切分；`Selection.matches` 不动（保持 raw 两侧一致，存量 selection_json
   零迁移）。
2. **存量不处理**：用户已删除按错误分组导入的文档，不留迁移逻辑。
3. **勾选联动 + 统计**：右侧按勾选过滤文件、确认按钮旁给「将导入
   N 文件 / M 切片」。
4. **顺带优化两项**：章节树搜索框、文件清单加「首标题」列。
5. **DB 零结构变更**；不新增依赖（冻结铁律）；不碰 `databases/` 目录
   （codex 数据库收敛线并行施工）。

## 四、核心机制：title 校准切分（beta-5）

### 4.1 校准函数

`restore.py` 新增（与 `split_path` 同层）：

```python
def split_path_calibrated(path: str | None, title: str | None) -> list[str]:
    """path + title → 校准段列表（标题跨段时尾部合并为一段）。"""
    segs = split_path(path)
    tsegs = split_path(title)
    if (len(tsegs) > 1 and len(segs) >= len(tsegs)
            and segs[-len(tsegs):] == tsegs):
        return segs[:-len(tsegs)] + [" > ".join(tsegs)]
    return segs
```

- 仅当 **title 切出多于一段** 且 **path 尾部与 title 段严格相等**（strip 后
  逐段比）才合并——普通数据（title 单段）行为与现在完全一致；
- 合并后的标题段用 ` > ` 规范连接（与树节点路径的既有规范化一致）；
- title 缺失 / 对不上尾部 → 回退现行为，不劣化。

### 4.2 一致性规则（防树节点键冲突）

**同一个 path 字符串在一次还原/建树中只允许一种切法**：按 part_id 升序
首个切片的 title 决定，后续同 path 切片复用（`build_calibration(slices)
-> dict[path, segs]`）。否则极端数据（同 path 不同 title）会在章节树上
产生重复 path 节点键，破坏 el-tree 勾选状态。

## 六、前端勾选联动（纯前端计算，零新接口）

### 6.1 过滤规则（与导入语义精确等价，已推导验证）

设勾选（经 `minimalSubtreePaths` 最小化）后的子树集合 P，则右侧显示：

1. **段前缀规则**：某 p∈P 按段是 `file_path` 的前缀（含相等）→ 显示。
   （即文件位于勾选章节**之下**：勾选章节本身是文件节点、或文件在
   勾选子树内——与 `Selection.matches` 对切片的前缀方向一致）
2. **父文件规则**：p 对应树节点 `direct_slice_count > 0` → 该节点直属
   切片归其**树结构父节点**的文件 → 该父文件也显示。父文件不在 p
   之下、规则 1 覆盖不到，故必须单列。（父路径从树 JSON 递归建
   `Map<childPath, parentPath>`，规避 ` > ` 字符串歧义；被勾选父节点
   级联覆盖的子孙节点其直属切片已由父节点前缀规则收编，故仅对最小
   子树集合执行两条规则即可精确）

不勾任何节点 = 整包 = 显示全部（与现状一致）。「继续勾选」编辑模式
同样生效。勾选变化时文件分页重置到第 1 页。

## 九、已知局限（如实记录）

1. **章节名**含 `>`（非标题位置）无法区分——path 字符串本身歧义，无
   真相源字段（`catalogue`/`kos_path` 实测为空），维持现状。
2. 同父下真实章节 `A` 与标题 `A > B` 并存时：勾选章节 `A` 会顺带拉入
   标题 `A > B` 的切片（字符串前缀固有歧义，raw 匹配两侧自洽使然）。
3. 校准按 part 序首个 title 决定——同 path 不同 title 的罕见数据取其一。
4. 跨段 title 的尾部恰好等于一段**真实章节链**时（如 path `X > A > B`、
   title `A > B` 而 A 本就是真文件节点）会被误并为文件 `X`、标题
   `A > B`——无真相源字段可判别，与局限 1 同属 path 字符串固有歧义。
   「title 对不上尾部 → 回退」用例不覆盖此情形（尾部是能对上的）。

## 十一、实施审查修订（beta-4）

实现后独立审查补出两个 beta-3 未覆盖的链路，beta-4 一并收敛：

1. 含 `>` 的标题成为父节点时，其语义段边界必须通过文档级前缀树向后代
   path 传播；否则后代记录只携带自己的末级 title，会重新产生假层级和重复
   `el-tree node-key`。
2. 子树拉取会先过滤祖先切片，因此选择记录额外保存 `path_hints`。服务端以
   当前 `RULE_VERSION` 的 TOC 树生成并校验该提示，不信任客户端自报边界；
   恢复结果再把校准段写入内部 JSONL 字段，解析器复用该字段，保证
   “全量预览—子集恢复—重同步—挖掘标题链”四处同义。
3. TOC 节点新增 `direct_part_min/direct_part_max`。前端按选中子树的直属切片
   重新聚合文件的切片数、首标题和 part 范围，不再复用整包文件统计。
4. 树过滤同时监听过滤词和 TOC 数据；刷新或切换文档后，在 `nextTick` 后
   对新树重新应用当前过滤词。

版本由 beta-3 继续提升为 `RULE_VERSION=beta-4`，解析器由 1.1.1 提升为
1.1.2，确保审查前生成的 TOC 缓存和解析快照不会被误复用。raw path、
`Selection.subtrees` 与 `Selection.matches` 的含义保持不变。

## 十二、双还原模式修订（beta-5）

- 一个 `source_id` 的首次导入、重试和重同步固定使用同一种具体模式；
  `auto` 仅用于 TOC 推荐，不持久化。
- `product_document` 保留倒数第二级文件规则；`file_anchor` 选择 path 中最深的
  受支持文件后缀段作为文件，后续层级均为文件内章节。
- `.hwics/.chm` 是产品容器而非文件锚点；无锚点切片计入 `unassigned`，不静默
  回退产品文档规则。
- TOC 一次扫描生成两套轻量预览，前端本地切换；确认导入时把具体模式写入
  `selection_json.restore_mode`，无需数据库迁移。
