01 · OVERVIEW

系统概览

三分钟认识 AgenticKB：它是什么、谁在用、以什么形态交付。

它是什么

知识生产与知识消费一体的团队知识平台：原始资料进来，被加工成可检索的证据与可复用的制品。一切知识以可追溯的证据为底座——每条结论都能回到原始出处。

谁在用

系统管理员编排加工范式、配置服务；域管理员管理本域用户；普通用户建库、检索、消费制品。而 Agent 是第一等公民——通过 MCP 协议直接使用知识库。

怎么交付

单容器一体化交付：Web 界面与全部服务一次部署、开箱即用，无需逐个搭建组件。支持多域隔离（域间资源互不可见）与品牌外观定制。

05 · FOR AGENTS

Agent 接入

系统通过 MCP 协议（Model Context Protocol，Agent 连接外部工具的开放标准）对 Agent 开放能力。任何支持 MCP 的 Agent 或客户端，配置一个地址和密钥即可使用。

查 · SEARCH search_knowledge

语义检索知识库，返回带出处的证据引用。Agent 提问的第一站。

读 · READ get_knowledge

统一读取入口：浏览域 → 库 → 目录的知识树，或按 ev_ / doc_ / st_ / art_ 引用逐层深读。

传 · UPLOAD manage_files

上传、替换文档；新资料自动进入挖掘队列，越用越全。

用户级密钥 · 精确开放范围

人人一把独立 MCP 密钥；管理员可精确配置开放范围——开放哪些工具、哪些知识库、哪些制品。

AGENT 调用示意
# 1. 检索：拿到带出处的证据引用
search_knowledge("版本升级的注意事项", kb="配置知识库")
→ [{ ref: "ev_9f2c…", text: "…", source: "配置指导 §4.1" }]

# 2. 深读：按引用取原文 / 查结构 / 读制品
get_knowledge(ref="ev_9f2c…")
get_knowledge(ref="art_0b31…", query="…")

# 3. 补充资料：上传新文档，自动进入挖掘队列
manage_files(action="upload", path="./新版指导.pdf")

知识对象层（L2） 建设中

知识架构 · 统一身份与关系平面

给对象与关系一个统一的身份平面：本体定义「类」，语义对象是实例化的结果——同一对象被证据引用、被图谱连接、被制品挂载，一处定义、处处引用。

核心概念

  • 本体 = 类：类型表 + 边规则
  • 语义对象 = 实例：稳定身份、可持续修正
  • 跨形态统一：ev_ / st_ / art_ 共享对象身份

建模方式

  • 页面配置即可建模，零代码
  • 存量对象按导入方案批量纳管
  • 域类型包：类型可按域复用

治理原则

  • 机器提议、人裁决
  • 变更候选两阶段门禁
  • 人工修正保护（不被自动覆盖）
  • 别名并入身份解析

统一管理动词

  • 进 · 认 · 联 · 改 · 发 · 退
