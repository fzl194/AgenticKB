## 第一部分：全格式审计

### 0. 审计结论先行

M3 当前交付的是 **7 条单后端 fast-path**，而不是规格中的结构化解析地基。按
SRS §4.6-§4.9 的主线（Parser Adapter → BackendParseArtifact → Normalizer →
Reconciler → Quality Gate）逐环检查：

| 主线环节 | 规格要求 | 当前状态 | 判定 |
|---|---|---|---|
| Parser Adapter | 库输出→BackendParseArtifact 映射 | 7 个 adapter 存在，但 PDF adapter 内嵌大量文档级规则（1240 行） | 部分越界 |
| BackendParseArtifact | 可持久化、可 replay（§9.5） | 仅 MD/TXT 保留 `raw_output`；Office/PDF/HTML 无序列化、无持久化、无 replay | **缺失** |
| Parse IR Normalizer | 坐标/类型/span/关系统一 | 类型映射存在；bbox 语义、表格文本、cell 级证据在各格式间不一致 | **不一致** |
| Structural Reconciler | C08 | **零实现**（PDF adapter 内嵌 `_annotate_furniture` 越权代行） | **缺失** |
| Parse Quality Gate | C09 | **零实现**（无指标、无决策） | **缺失** |

### 0.1 跨格式不变量违规汇总（本轮必须修复）

| # | 不变量（SRS 依据） | 违规事实 | 违规格式 |
|---|---|---|---|
| I-1 | bbox 统一 `(x0, top, x1, bottom)`（§7.4 visual_region） | PPTX `_bbox_of` 返回 `(left, top, width, height)`——后两个分量是宽高不是右下角 | PPTX |
| I-2 | 表格 Element.text 全格式统一可检索序列化 | XLSX/PPTX/HTML 表格元素 `text=""`（空串），检索无从命中 | XLSX, PPTX, HTML |
| I-3 | TableAsset 是事实源，Element.text 是 rendered view | 三种空文本格式的 Element.text 不可由 TableAsset 重算；各格式序列化方式不统一（MD pipe、DOCX/PDF tab、其余空） | 全部 |
| I-4 | 可取得原生单元格位置时 TableCell 必须有独立 source_span_id | DOCX 单元格全部回落到元素的唯一 span（所有 cell 指向同一 span）；PPTX/HTML/PDF cell 无 span | DOCX, PPTX, HTML, PDF |
| I-5 | parser/规则配置/依赖/normalizer 任一变化改变 effective pipeline fingerprint | ParseIdentity 只有 parser_fingerprint+normalizer_version；PDF 的十几项启发式阈值（HEADING_SIZE_RATIO、LINE_TOP_TOLERANCE、段落 gap 系数、表合理性参数…）全部不在指纹内——改规则不改指纹，违反 §3.5 | 全部（PDF 最重） |
| I-6 | backend raw artifact 可持久化 + replay | `BackendParseArtifact` 无 to_dict/from_dict；shadow service 只持久化 IR JSON；§9.5 "adapter mapping bug → 用 raw artifact 重新 normalize" 无代码路径 | Office/PDF/HTML |
| I-7 | 不支持/未解析结构必须进 diagnostics，不得静默丢失 | DOCX 图片/页眉页脚/脚注/批注/文本框/嵌套表格静默丢弃；XLSX 图表/图片静默丢弃；PPTX notes/chart/SmartArt 静默丢弃；MD 图片链接静默降级 unknown 且无 warning；PDF 图片/公式静默丢弃 | 全部 |
| I-8 | 不把 adapter 特有类型泄漏进公共 Parse IR | PDF 的 `warning` 块类型是 adapter 私有词汇；MD `image`→`unknown` 是静默类型退化；元素类型集合本身合规（validator 保证） | PDF, MD |

### 1. Markdown（legacy_markdown.py + normalizer.py）

| 维度 | 现状 |
|---|---|
| container | 单一 `section`（c-doc），无页概念 ✓ |
| element type | heading/paragraph/list_item/code/quote/table；**image→unknown、raw_html→unknown**（映射表显式降级） |
| relation | parent_of（heading 弹栈）+ next_in_reading_order ✓ |
| structured asset | pipe table → TableAsset（首行 is_header 约定）✓ |
| source evidence | 行级 EvidenceSpan（line_start/line_end + raw_text 切原文）✓ 行可回溯（§A01） |
| raw artifact | `raw_output` = 解码后源文本 ✓（唯一保留 replay 原料的格式） |
| 已知丢失结构 | 图片（src 不进 annotations 结构、不计数、无 warning）；链接（href 完全丢弃，token 层未收集）；HTML 块内容 |
| parser/normalizer fingerprint | `legacy_markdown@1.0.0#markdown-it-py-<ver>` + `legacy-line@1`；无规则配置概念 |
| 测试覆盖 | test_legacy_markdown.py(11) + test_normalizer.py(15)，无图片/链接诊断断言 |

判定：**地基最稳的格式**。缺口集中在 I-7（图片/链接无可见诊断）。

### 3. DOCX（native/native_docx.py）

| 维度 | 现状 |
|---|---|
| container | 单一 `section`（伪造文档级容器）；OOXML `w:sectPr` 分节未识别 |
| element type | heading（style API 判级，Heading N/标题 N）/paragraph/**table** |
| relation | parent_of + next_in_reading_order ✓ |
| structured asset | TableAsset：gridSpan/vMerge 合并展开（矩形合并 row_span 已修）✓ |
| source evidence | paragraph_index / table_index（w:p 计数含空段，索引稳定）✓；**表格单元格无独立证据**——所有 cell 的 source_span_id 回落到表格元素唯一 span（`_cell_span_id` 无 evidence_index 时取 spans[0]） |
| raw artifact | 无序列化、无持久化（I-6） |
| 已知丢失结构（全部静默） | ① **列表语义**：`w:numPr` 完全忽略，列表项退化为普通 paragraph，层级丢失；② 图片（inline + floating）；③ 页眉/页脚；④ 脚注/尾注；⑤ 批注；⑥ 文本框（`w:txbxContent`）；⑦ 嵌套表格（cell 内 `w:tbl` 不遍历，内容直接丢失） |
| fingerprint | `native_docx@1.0.0#python-docx-<ver>`；规则（heading 正则）不在指纹 |
| 测试覆盖 | test_native_docx.py(8)：标题树/合并格/索引证据；无列表/诊断断言 |

判定：**六类结构静默丢失 + 单元格证据缺失**，违反 I-4/I-7。

### 4. XLSX（native/native_xlsx.py）

| 维度 | 现状 |
|---|---|
| container | workbook → sheet 层级 ✓ |
| element type | **仅 table**——整 sheet 无条件一张语义表 |
| relation | 无（sheet 间无关系） |
| structured asset | TableAsset：公式/展示值双读 ✓、合并区域展开 ✓、cell 级 A1 native_ref span ✓（全格式中证据最全） |
| source evidence | 每 cell 一个 EvidenceSpan（sheet+cell 坐标）✓ |
| raw artifact | 无（I-6） |
| 已知丢失结构 | ① **Excel Table（ws.tables）不识别**——命名表被当普通区域；② **连续数据区域不切分**——一 sheet 多张表/表+备注混排时全部混进一张网格（空行空列也计入 rows/cols）；③ 隐藏行/列状态不保留；④ 图表（ws._charts）静默丢弃；⑤ 图片（ws._images）静默丢弃；⑥ is_header 盲目取 r==0（无表头语义检测） |
| Element.text | **空串**（I-2/I-3）——检索无法命中表格内容 |
| fingerprint | `native_xlsx@1.0.0#openpyxl-<ver>`；几何上限常量不在指纹 |
| 测试覆盖 | test_native_xlsx.py(8)：双读/合并/稀疏防御；无区域切分/图表诊断断言 |

判定：**"整 Sheet 一张表" 是语义错误**（用户第三步指令明确禁止），叠加 I-2/I-7。

### 5. PPTX（native/native_pptx.py）

| 维度 | 现状 |
|---|---|
| container | slide（无页码伪造，EMU 尺寸）✓ |
| element type | heading（title placeholder + 页顶短行启发式）/paragraph/table/figure |
| relation | parent_of（跨 slide 重置 ✓）+ next_in_reading_order |
| structured asset | 表格 TableAsset（span 库 API 直读）✓；**figure 无 FigureAsset**（图片 hash/bytes 未提取） |
| source evidence | shape 级 visual_region bbox + slide/shape index ✓；但 **bbox 语义错误**（I-1）：`(left, top, width, height)` 而非 `(x0, top, x1, bottom)` |
| 阅读顺序 | **直接等同 shape XML 顺序**——不做任何几何排序；用户指令明确禁止 |
| 文本框粒度 | **整个 text_frame.text 一块**——框内多段落/多级 bullet 全部粘成一段，`p.level` 丢失 |
| raw artifact | 无（I-6） |
| 已知丢失结构 | ① notes（has_notes_slide 不读）；② chart（has_chart）；③ SmartArt（graphicFrame）；④ **group shape 不递归**（组成员全部丢失，已知 LOW 缺口）；⑤ 图片资产不物化 |
| Element.text | 表格空串（I-2） |
| fingerprint | `native_pptx@1.0.0#python-pptx-<ver>`；标题带启发式（0.30/24chars）不在指纹 |
| 测试覆盖 | test_native_pptx.py(8)+新增 v9 若干；无 bbox 角点/段落拆分/notes 断言 |

判定：**五维缺陷**（bbox/阅读序/段落粒度/静默丢失/空文本），本轮工作量最大的 Office 格式。

### 6. HTML（native/native_html.py）

| 维度 | 现状 |
|---|---|
| container | 单一 `dom_document` ✓ |
| element type | title/heading/paragraph/list_item/code/table/figure |
| relation | parent_of + next_in_reading_order ✓ |
| structured asset | TableAsset（rowspan/colspan 直读 + 单值 10k 上限）✓ |
| source evidence | xpath native_ref ✓；表格 cell 无独立 span（I-4） |
| raw artifact | 无（I-6） |
| 已知丢失结构 | ① **嵌套列表**：`li` 命中块标签后 `itertext()` 吸收嵌套 `ul/ol` 全部文本，子列表项既不成元素、文本又被父项吞并（层级+内容双损）；② 链接（a href 丢弃）；③ `figure/figcaption`（语义容器不识别，figcaption 文本被并入 figure 块或丢失）；④ `table>caption`（表题丢弃）；⑤ 语义容器（article/section/nav/main/aside）无痕迹 |
| **面积上限缺失** | `_span_attr` 只钳单值 ≤10k，但 `rowspan*colspan` 乘积无上限——`rowspan=10000 colspan=10000` 会向 occupied 写 10⁸ 条目（内存 DoS）。用户指令明确要求面积上限 |
| Element.text | 表格空串（I-2） |
| fingerprint | `native_html@1.0.0#lxml-<ver>`；span 上限/编码策略不在指纹 |
| 测试覆盖 | test_native_html.py(8)：标题/列表层级/rowspan/嵌套表行归属；无嵌套列表独立成元素/面积炸弹断言 |

### 7. PDF（native_pdf.py + pdf_normalizer.py）

| 维度 | 现状 |
|---|---|
| container | page（1 基页码，pt 宽高）✓ |
| element type | heading/paragraph/table + page_header/page_footer/page_number（家具标注）+ 私有 `warning` 块（I-8 泄漏源） |
| relation | 页内 next_in_reading_order（跨页不连 ✓）+ parent_of |
| structured asset | TableAsset（坐标网格推 span，三层识别策略+第四层片段聚类）✓ |
| source evidence | 行/段/表 bbox visual_region ✓；**表格 cell 无独立 span**（I-4：pdfplumber rows[i].cells[j] 有坐标却未生成 cell 级证据） |
| raw artifact | `raw_output=""`，注释明说"replay 直接重跑 parse"——**违反 §9.5**（I-6） |
| 家具规则越界 | `_annotate_furniture`/`classify_furniture` 是**文档级跨页规则**，却在 adapter 内执行（SRS §4.8 明确是 Reconciler 职责）；adapter 因此需要两遍扫描全文档 |
| 双栏跨栏粘连 | v8 `reorder_columns` 已做左右分栏，但通栏行判定有缺陷：`left = x1 <= mid+10`——左栏行略过中线即被误判通栏，成为错误锚点打乱带划分（跨栏粘连残留） |
| 标题误杀（残留） | 防御规则堆叠后误杀真标题：① `digit_leading_noise` 一刀切杀 "3D 打印…"/"5G 网络…" 类数字开头真标题（by_pattern 不命中时无豁免）；② `dense_frags ≥4` 用**全页字符**（含表格字符）计算，标题行 top 带与表格行重叠时误杀；③ 宽字距 CJK 标题（"第 三 章 …"）被 x-gap 判多片段误杀 |
| 表格 bbox/cell 不一致 | v6 数据核心收缩后：bbox 用收缩框，**cells 仍来自原 extract**——报告的 bbox 与 cell 内容覆盖范围不一致（已知缺口 p28：收缩框外行仍在 cell 里）；`bbox_override` 是旁路 hack（pdfplumber Table.bbox 只读） |
| 死代码 | `_shrink_table_below_headings`（已解接线仍残留）、`_is_plausible_table` 重复 except 子句（不可达）、`reorder_columns` 死循环 `for group in (left,right): pass` |
| fingerprint | `native_pdf@1.0.0#pdfplumber-<ver>`；**十几项启发式阈值全部不在指纹**（I-5 最重灾区） |
| 测试覆盖 | test_native_pdf.py(15) + test_pdf_cjk_lines.py(30，未提交 v9 增量) |

判定：**单文件 1240 行、三轮验收补丁堆叠**，正是用户指令"不再膨胀 adapter"点名对象。跨元素/跨页规则必须外迁。

### 8. shadow_parse 链路（服务层）

- 只持久化 IR JSON（`_persist_ir`，内容寻址 key → parse bucket）；backend artifact 用后即弃。
- 幂等 = 复用 SUCCEEDED 投影或重放同字节 IR；**无 "raw artifact → 重新 normalize" 路径**（§9.5 A09 场景无实现）。
- 无 Reconciler/Quality Gate 环节（M4 未启动，本轮补最小实现）。

### 9. 测试体系审计

- 用例分布：parse_adapters 10 文件 ~121 例、shadow_parse 18 例、file_inspector 23 例、contracts test_parse_ir 30 例。
- **无跨格式 contract test**（唯一多格式 e2e 只断言"能进 IR"，不断言同一不变量）。
- **无 golden corpus**（全仓无 corpus 目录；M3 报告 §6.7 明确记录"用户不需要评测体系"——本轮按新指令推翻该结论）。
- 质量结论形态 = "元素数量变化"（D-030/031 的"2609→1614"式报告），无覆盖率/准确率指标——用户指令明确禁止以此作为质量结论。

## 第二部分：分阶段整改计划（本轮执行）

> 纪律：严格 TDD（每项先 RED 后 GREEN）；不动 auth.yaml 等无关配置；
> 保留工作区已有未提交改动（v9 验收增量）；旧链路（ingestion/stages）零改动。

### Phase 1 —— 契约与不变量（先立规矩）

1. `contracts/parser_adapter.py` v1.2：
   - `ParseRuleConfig`（frozen dataclass，含各 adapter 启发式阈值 + `config_fingerprint()`）；
   - `BackendParseArtifact.to_dict()/from_dict()`（JSON round-trip，为持久化/replay）；
   - `effective_pipeline_fingerprint(parser_fingerprint, normalizer_version, rule_config_fingerprint, dependency_fingerprint) -> str`。
2. `contracts/parse_ir/types.py`：`ParseIdentity` 增加 `rule_config_fingerprint: str | None`；validator 增加 bbox 顺序校验（x0≤x1, top≤bottom）。
3. `tests/parse_adapters/test_cross_format_contract.py`：八条不变量（I-1..I-8）对全部 7 格式统一断言——先 RED。

### Phase 2 —— 共享 normalizer 骨架

4. `parse_adapters/rendered_text.py`：`render_table_text(asset)` 统一序列化（行 `\n`、列 `\t`、只取原点 cell）；所有 normalizer 的表格 Element.text 一律由 TableAsset 渲染（I-2/I-3）。
5. `native/_base.py`：cell 级 span 构建钩子（evidence_index 机制推广到 DOCX/PPTX/HTML/PDF）；adapter 私有类型过滤（`warning` 等不进 IR）。

### Phase 3 —— 逐格式修正（每格式独立 RED→GREEN）

6. DOCX：`w:numPr`→list_item(level=ilvl+1)；cell 级 native_ref+span；六类结构（图片/页眉页脚/脚注/批注/文本框/嵌套表格）计数进 diagnostics（嵌套表格额外抽取为独立表格块）。
7. XLSX：Excel Table 优先 → 连续数据区域切分 → 退化整 sheet（带 `region_strategy` 注记）；隐藏行列注记；chart/图片诊断；Element.text 渲染。
8. PPTX：bbox 角点化；text_frame 按段落拆分（bullet level）；shape 几何带排序阅读序；notes 保留；group 递归；picture → FigureAsset+binary_assets(hash)；chart/SmartArt 诊断。
9. HTML：嵌套列表独立成元素（li 直属文本与子列表分离）；links 进 annotations；figcaption/caption→caption 元素+caption_of；语义容器路径；rowspan×colspan 面积上限；表格文本渲染。
10. PDF：修通栏行误判（按跨沟判定）；修数字开头真标题误杀 + dense_frags 用行内字符；表格收缩框与 cell 内容一致（按收缩框过滤网格）；删除死代码。
11. MD/TXT：图片/链接计数进 diagnostics；TXT 退化输入固化用例；确认无 token 切片（守卫测试）。

### Phase 4 —— Reconciler + Quality Gate + replay

12. `mining/parse_reconciler/`（C08 最小）：家具分类/标注（从 PDF adapter 迁入，IR 级跨页规则）、caption_of 绑定、跨页表格 continuation_of（保守：列数一致+连续页+表头相似）、跨页段落 continues_on（保守：栏位一致+无句终点）；patch log；`reconciler_version` 回写 ParseIdentity。
13. `mining/parse_quality/`（C09 最小）：六类指标（字符覆盖率/结构准确率/表格完整率/证据可定位率/阅读序正确率/warning 分布）+ PASS/WARN/FAIL 决策（quality profile）。
14. `shadow_parse`：backend raw artifact 序列化持久化（artifact_class=backend_raw）+ `renormalize()` replay 路径 + 等价性测试。

### Phase 5 —— Golden corpus + 基准

15. `tests/golden_corpus/`：≥45 份（7 格式 × 正例/反例/复杂/退化），生成器确定性可重建；每份带期望标注（标题序列/段落锚文本/表格网格/阅读序锚）。
