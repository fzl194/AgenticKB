## 2. 交付物清单

### 2.1 Object Store（`knowledge_mining/mining/contracts/storage/` + `infra/object_store/`）
- **Port 改 location 寻址（D-020）**：`ObjectStorePort` 全 async 按 `ObjectLocation(bucket,object_key,version_id?)` 寻址；业务身份 `storage_object_id` 改由 Repository(PG) 持有。
- `FakeObjectStore`：文件系统后端、**跨实例持久**、全 Port 含 multipart、sha256 校验。测试与开发用。
- `MinioObjectStore`：minio SDK **lazy import**（顶层无 minio 引用）；S3Error→StorageError 映射；凭据不进 `__repr__`；multipart 留 seam（待 MinIO 部署后接通）。
- `ObjectStoreConfig`（from_yaml/from_dict，secret 屏蔽）+ `make_object_store` factory + `build_object_key`（SRS §8.1 `v1/ab/cd/<sha256>`）+ `system/storage.yaml`（默认 fake）。

### 2.2 Repository 协议 + Upload 编排（`contracts/file_management.py` + `file_management/`）
- 5 个 `@runtime_checkable Protocol`：StorageObject / UploadSession / DocumentCurrentContent / FileAudit / Quota Repository。
- `DocumentCurrentContent.set_current_content` 乐观并发（content_revision）→ `DocumentRevisionConflict`（SRS §C01 409）。
- `UploadSessionService`：initiate（幂等+配额 reserve+presign staging）→ stage → **complete**（stat 校验 size/sha256 → 注册 StorageObject + Document 当前内容乐观更新 + 审计 + 配额 commit；幂等；sha256 dedup 复用）→ abort。状态机 `assert_transition` 守卫。
- in-memory fake repos（测试）+ PG repos（学 KbDB 风格，PG-gated）。

### 2.3 File Management 服务 + 路由（`file_management/{file_service,router}.py`）
- `FileManagementService`：list/get/download_url/replace_content(copy-on-write)/rename/move/soft_delete/restore/purge_request。改名/移动不动对象字节；乐观并发。
- FastAPI router：SRS §C01 资源边界 10 路由 + 依赖工厂 + 错误→HTTP 映射（404/409/410/413/422/503）。
- **迁移期共存**：未改 `DocumentService` / 现有 kb routes（grep 确认）。

### 2.4 Frozen Input + 安全 Intake（`frozen_input/`）
- `SafeIntake`：自实现 magic-byte 签名（**签名胜扩展名**）+ 加密检测 + archive 三限（文件数/展开大小/压缩比）+ 路径穿越防护，纯逻辑零依赖（SRS §2.4）。
- `FrozenInputService.freeze`（校验 AVAILABLE 后快照 `storage_object_id+raw_hash+content_revision`）+ `check_stale`（revision 漂移检测，SRS §3.2）。
- `ObjectStoreSourceArtifactReader`（兑现 D-020）：`open_stream`（流式 sha256 校验）/ `materialize_temp`（run-scoped 临时文件 + 校验 + cleanup；临时路径不进 DB，§10.2）。

### 2.5 迁移工具（`file_migration/`）
- `FileMigrationService`：migrate_document（verify-before-switch + sha256 全量比对 + 乐观并发）/ run（limit+dry_run）/ resume（幂等续跑）。
- 状态 PENDING→UPLOADING→VERIFIED→SWITCHED/FAILED；missing/revision_conflict/hash_conflict 分类计数；MigrationReport 字段 1:1 对齐 SRS §8.8。
- `MigrationInventory`/`ProgressStore` Protocol（FS + memory 实现；PG 版留接线）。

覆盖的关键验收（对应 SRS §A）：A16 大文件上传（multipart round-trip）、A17 重复提交幂等 + 物理去重、A18 改名移动不改对象、A19 软删恢复、A20 MinIO 故障→storage_unavailable、A21 对象完整性（sha256 校验）、A22 授权下载 presign、A13 恶意文件（archive 限制 + 路径穿越）、A23 本地文件迁移幂等、A25 临时文件隔离。

## 4. 关键决策摘要（详见 ADR-0003 D-020~D-025）

- **D-020**：ObjectStorePort 改 location 寻址（MinIO 原生模型，adapter 无需自带注册表）。取代 D-013#1。
- **D-022**：六边形分层——编排逻辑依赖 Repository Protocol，可离线全测。
- **D-023**：File Management 迁移期共存，不拆旧 DocumentService。
- **D-024**：SafeIntake 纯逻辑、签名胜扩展名；SourceArtifactReader 应用层组合落地。
- **D-025**：迁移工具 verify-before-switch + 乐观并发，不改读写路径。

## 6. 已知缺口（需后续里程碑或部署环境）

1. **双读（Phase 3）未接线**：M1.5 只做 Phase 2 回填；读侧统一「MinIO 优先 / 本地回退」未接入 DocumentService/serving。这是 M1 退出条件里唯一明显未完成项，留 M1 收尾或 M2 初补。
2. **MinIO multipart seam**：`MinioObjectStore.upload_part/complete/abort` 留 NotImplementedError（契约已锁，待 MinIO 部署后接通真 SDK + guarded smoke）。
3. **PG 实现未在本环境跑**：`repositories_pg.py` / PG inventory 已写、可导入，但需部署 PG 才验证（与现有 kb/ 测试同条件）。
4. **未接入 app 启动/CLI**：factory + service 就绪，但 main_control_service 启动时的依赖注入、storage.yaml 加载接线未做（需了解 service.py 配置加载后接）。
5. **迁移并发**：`run()` 顺序执行，批量并发留 TODO。
