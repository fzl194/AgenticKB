## 1. 范围与业务目标（用户业务语言）

M4 之前，解析结果只堆在"影子区"（临时仓库）：质量打了分但没人执行，好
结果进不了知识库，坏结果也没有硬性拦截。M4 建**成品入库**这一环，给用户
五条保证：

| # | 保证 | 实现机制 |
|---|---|---|
| 1 | **垃圾不入库** | 质量门禁 FAIL（空文档/覆盖率崩坏/全后端失败）→ Run 终态 FAILED，快照表零写入（应用层 + 记录层双保险） |
| 2 | **不张冠李戴** | 提交前最后核对文档当前 revision ≠ 冻结值 → Run 标 `SUPERSEDED`，不建快照（真 `FrozenInputService.check_stale` 接线） |
| 3 | **每份知识有出生证明** | 快照携带：来源对象/revision（links 行）、解析管线指纹（parser+normalizer+规则+依赖+reconciler+IR schema）、质量结论、产生它的 Run |
| 4 | **修复不重复花钱** | backend raw artifact 已持久化；`replay()` 用升级版 normalizer 重放产**新**快照，parser 零调用（A09） |
| 5 | **失败看得见、有备胎** | ParsePlan 有序后端链 + 尝试预算；主后端崩溃或质量硬失败 → 预算内自动换备胎；每次尝试一行审计事件（primary/fallback/repair/replay + 结局 + 原因） |

## 2. SRS 退出条件核对（§14 M4）

| 退出条件 | 结果 | 证据 |
|---|---|---|
| 低质量文档不会形成 READY Snapshot | ✅ | golden corpus 50 份端到端：6 个空/坏样本全 FAILED 零快照；FAIL 决策在 `SnapshotCommitService` 被记录层二次拒绝 |
| 可 fallback | ✅ | A05：primary 崩溃/质量硬失败 → 预算内自动切换，双 attempt 留档可审计；预算耗尽退化为 FAIL（不死循环） |
| 可 replay | ✅ | A09：raw artifact 重放 + 升级 normalizer → 新快照（新指纹），parser 调用数不变（e2e 与单测双重断言） |
| 过期输入不会自动发布 | ✅ | SUPERSEDED 终态（提交前 check_stale）；真库 e2e S4：revision 前移 → Run=SUPERSEDED、快照零产出 |

## 3. 交付物

### 3.1 契约层（M4.1）
- `contracts/state_machines.py`：Parse Run 状态机扩至 **13 态**——补
  `SUPERSEDED` 终态（§9.5 提交前校验失败）+ 4 条操作性补边（PARSING/
  NORMALIZING/RECONCILING→FAILED 崩溃终态、PARSING→FALLING_BACK 失败
  触发回退；§9.2 图未画，SRS §2.2/§9.5 语义要求，见 D-033）。
- `contracts/parse_plan.py`（新）：`ParsePlan`（primary + **有序**
  fallback 链 + 质量档位 + plan 版本）+ `AttemptBudget`
  （max_backend/repair_attempts、max_duration_seconds；链长超预算构造
  即拒）。
- `contracts/snapshot_store.py`（新）：`snapshot_fingerprint()`（domain +
  raw hash + effective pipeline + compiler + workflow 哨兵，任一变化必
  变指纹）、`SnapshotRecord`（quality 仅 PASS/WARN 可入，FAIL 记录层即
  拒）、`SnapshotSourceLink`（来源对象/revision）、`SnapshotRepository`
  Protocol（幂等 commit / mark_lifecycle 单向）。

### 3.2 质量门禁补全（M4.2，WP8）
- `parse_quality/gate.py`：五值决策 `PASS/WARN/REPAIR/FALLBACK/FAIL` +
  `RepairRequest`（目标容器定位）/`FallbackRequest`（原因码）+ **预算
  感知降级**（预算内覆盖失败→FALLBACK；耗尽→FAIL+`budget_exhausted`
  issue；空容器→预算内 REPAIR，耗尽→WARN 可见）。
- `parse_quality/metrics.py`：新增 `empty_container_ids`（无元素**叶子**
  容器；无元素-容器绑定的 legacy 形态宁缺勿误报）。
- 兼容性：`evaluate(metrics)` 单参调用行为不变（全部 M2/整改轮调用方与
  golden 守卫零回归）。

### 3.3 Parse Run 状态机接线 + attempt 审计（M4.3，WP7 切片）
- `shadow_parse/contracts.py`：`PARSE_RUN_STATUSES`（单一事实源对齐）、
  `ParseRunRecord.snapshot_id`、`set_status`（执行内推进，非法跳转抛
  `IllegalTransition`）、`insert`（追加新执行行）、
  `ParseAttemptRecord`/`ParseAttemptRepository`。
- memory + PG 双仓储同步实现；**幂等锚点上移**：Run 是执行历史，同
  (document, hash, parser) 多行合法（FAILED 重跑/A09 重放/A07 升级），
  幂等由 Snapshot 指纹承担（§2.2 本意）。
- 010 DDL（双方言）：status CHECK 扩 13 态、`snapshot_id` 列、
  `asset_parse_run_attempts` 表（`(parse_run_id, attempt_index)` 唯一）、
  009 的幂等唯一索引降级为普通索引。

### 3.4 快照转正（M4.4，WP9 核心）
- 新包 `snapshot_store/`：`SnapshotCommitService`（提交协议 = ①IR 制品
  完整性校验（§8.6 注册行+字节双在）→ ②pre-commit revision check →
  ③指纹合成 → ④幂等提交；任何失败都在写仓储**之前**，不产生半成品）。
- `MemorySnapshotRepository` + `PgSnapshotRepository`（写真
  `asset_document_snapshots`/`links`，ON CONFLICT 指纹幂等，link 存在
  跳过；lifecycle 单向 READY→DEPRECATED/REVOKED）。
- **旧链路串线隔离（审计驱动，D-033）**：新链快照 workflow 绑定四元组
  填哨兵 `new-parse-chain@1`——legacy `find_reusable_snapshot` 的
  `workflow_graph_hash IS NULL` 分支与真实 workflow 分支均永不匹配新行；
  004 的 workflow-content 唯一索引重建为排除指纹行的 partial（新链唯一
  性由指纹索引承担，§8.3A「唯一性演进」）。
- `parse_operator/DocumentParseService`（编排器）：ParsePlan → Run 状态
  机推进 → 每 attempt 一个 `ShadowParseService`（复用制品落存/replay，
  零代码复制）→ 五值决策分派（PASS/WARN 提交、FALLBACK 换链、REPAIR
  无执行器时保守 WARN+`repair_unavailable` 可见、FAIL 终止）→
  `replay()`（A09 入口，normalizer 可覆盖注入）。

## 5. 明确不做 / 未达成（不以"已预留"冒充"已支持"）

1. **切片（M5/WP10）**：快照无 segments，`compiler_fingerprint` 列暂 NULL。
2. **element/container/relation 的 PG 查询投影**：WP9 提及但当前零消费
   者（M5 编译器读 IR 对象、M6 Knowledge Access 才需要）——按 YAGNI 推迟，
   非契约缺失。
3. **真实第二后端**（Docling/云 OCR，M3B）：fallback **编排机制**已建成并
   测试（stub 双后端），真备胎等用户提供模型配置。
4. **Router policy 版本化**（M3B）：ParsePlan 有 `plan_version` 哨兵字段。
5. **REPAIR 执行器**：门禁可产出 REPAIR 请求（目标容器+原因），M4 无页级
   修复后端——编排层如实降级（有备胎→FALLBACK；无→WARN+`repair_unavailable`）。
6. **workflow 挂接**（M6 WP11）：转正入口是服务层（脚本/测试/e2e 可调），
   未接"更新知识"按钮。
7. **Build 选择新快照**（M6 WP12）：新链快照不进任何 build 绑定。
