> 日期：2026-08-21
> 分支：`feat/doc-parse-platform-m0`
> 决策留档：ADR-0003 **D-036**
> 上游：M0-M5（契约/文件地基/影子解析/原生解析+整改/质量门控/切片编译）

## 1. 业务目标

把新解析链路接入挖掘工作流：**「更新知识」任务可以走新算子**——解析与
切片拆分为两个标准算子（SRS §10.2），七套挖掘范式模板升级 v2；切片以
兼容格式落现有资产表，下游增强/检索单元/向量化环节**零改动**消费。

| 新 workflow 显式 parse/segment（A11） | ✅ v2 模板七套全量编译通过，document_parse→segment_compile 固定骨架（编译器校验存在性+顺序） |

| 切片进 Build/发布选择 | ⚠️ 部分：切片/快照已落正式表（asset_raw_segments/snapshots，Build 可选）；**在线发布链路与范式构建器前端面板未接**（见 §5） |

## 3. 交付物

### M6.1 算子目录 v2（`b3f50ea`）
- `document_parse`（raw_files→parsed_documents）+ `segment_compile`
  （parsed_documents→parsed_segments）注册为 **FIXED** 算子；
- 编译器**版本感知骨架**：v2 manifest 要求新两算子（不要求旧的），
  v1 维持 parse_segment——历史任务不受影响；
- 七套范式模板 v2（`builtin_templates_v2`）；
- **参数档位**（范式构建器头部面板契约）：解析（质量档/后端预算）+
  切片（上限/下限/合并/表格视图/章节路径/图题——与 SegmentPolicy
  一一对应）。

### M6.2 handler 接线（`aa4be4b`）
- `document_parse_handler`：经注入服务执行新链解析，产出
  `ParsedViaNewChain`（run/快照/IR 指针 + raw_file 透传）；
- `segment_compile_handler`：快照 IR + 档位 → 切片 →
  `to_raw_segment_data` 兼容投影进 `DocumentContext.segments`——
  **下游算子零改动**；
- 组件未接线显式 FAILED（不静默混跑旧解析）；空输入 SKIP。

### M6.3 服务门面 + 组合根（本次提交）
- `DocumentParseFacade`（同步门面）：raw_file → 文档当前对象（注册行
  取真实 bucket/key）→ 冻结输入 → DocumentParseService → 解析指针；
  旧链 storage_path 文档 → None（SKIP 不混跑）；Run 终态非成功 → 抛错；
  后端预算参数映射进 ParsePlan；async 桥接双环境（线程/事件循环）；
- `SegmentCompileFacade`：档位 → SegmentPolicy → 编译 + 切片列表；
- `build_new_chain_services` 组合根：memory（测试）/ PG+MinIO（生产，
  传 pool 即切换）双形态，注入 `runtime.services`。

## 5. 明确不做 / 未达成（不以"已预留"冒充"已支持"）

1. **范式构建器前端**（R7）：锁定头部节点 + 参数面板未做——后端档位
   契约与参数校验已就绪（SegmentCompileOptions/DocumentParseOptions），
   kb-ui 范式编辑器改造独立排期；
2. **在线发布衔接**：新链快照可被 Build 选择（正式表），但「更新知识」
   按钮仍走 v1 链路——**切换开关**（模板 v2 投产/灰度）需运维流程配合，
   属 M6 收尾或 M7 范围；
3. **v2 模板投产灰度**：模板已编译验证，未发布为默认模板（mining-
   workflow-rollout-runbook 的灰度流程未走）；
4. executor 全链（input_ingest 产出 raw_file 的 document_id/mime 字段
   对接）以 e2e 脚本构造为准——生产 input 阶段需确认字段供给。
