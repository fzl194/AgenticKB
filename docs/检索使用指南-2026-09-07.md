# 知识库检索使用指南

> 适用版本：1.0.2（master `ae8ab9a`）。面向想检索知识库的同事：脚本/HTTP 直调、AI Agent（MCP）接入都覆盖。
> 网页检索、HTTP 接口、MCP 工具**背后是同一个检索引擎、同一个入口**，行为与结果完全一致。

---

## 1. 一分钟总览

系统只有**一个检索执行入口**，三种使用方式殊途同归：

| 方式 | 适合谁 | 入口 |
|---|---|---|
| 网页「知识库 → 检索」tab | 所有人 | 平台界面，登录即用 |
| HTTP POST（§4） | 脚本、系统集成 | `POST /api/v1/paradigm/{paradigmId}/search` |
| MCP 工具（§5） | AI Agent | `http://<服务器IP>:9000/mcp` + 个人密钥 |

检索前必须满足两个前提：

1. **目标知识库已完成一次成功的挖掘**（网页库详情页顶部「检索就绪度：语义可搜」即可）。部分文件失败不影响——成功入库的部分可检索；重新点挖掘会自动跳过已成功的、只重挖失败的。
2. **调用身份对该库有读取权限**：库主 / 库成员 / 库是 public，三者满足其一（详见 §6）。

---

## 2. 核心概念

```
知识域 domain ──> 知识库 knowledge base ──> 文档 document ──> 证据 evidence ──> 结构 structure
```

- **domain**：部署通常只有一个域（默认 `default`）。账号属于哪个域，检索就用哪个域。
- **paradigm（检索范式）**：一条可组合的检索管线（召回 → 过滤 → 组装）。每个库可绑定范式，未绑定用官方默认。**调用方一般不用关心**——HTTP 先调 resolve 拿范式 id；MCP 完全自动。
- **三种引用（ref）**：检索/读取结果里返回的 opaque 引用，原样回传即可进一步取内容：
  - `ev_…`：一条证据（检索命中的片段）
  - `doc_…`：一篇文档（整篇分页读取）
  - `st_…`：一个结构节点（章节/表格，可导航、可查表格）
- **统一响应协议**：检索返回 `{query, evidence[], has_more}`，每条 evidence 带 `ref / type / content / source / truncated`。**没有 score、rank、内部 id**——网页和 MCP 拿到的也是同一形状。

## 3. 准备工作

### 3.1 HTTP 方式：登录拿 token

所有请求走平台网关（默认 80 端口），前置登录换取 JWT（默认 12 小时有效）：

```bash
# 1. 登录（用你平时的平台账号密码；无密码的工号成员可不传 password）
curl -s -X POST http://<服务器IP>/api/control-plane/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username": "zhangsan", "password": "******"}'
# → {"token": "eyJhbGciOi...", "user": {...}}

TOKEN="eyJhbGciOi..."

# 2. 查你有哪些库、拿到 kbId（检索的必传参数）
curl -s "http://<服务器IP>/api/control-plane/api/v1/proxy/default/mining/api/kb?domain=default" \
  -H "Authorization: Bearer $TOKEN"
# → [{id: "kb-xxxx", name: "...", visibility: "private", my_role: "owner", document_count: 123}, ...]
```

### 3.2 MCP 方式：生成密钥、勾开放库

MCP 是**用户级**接入——一人一钥，密钥决定 Agent 能看到什么：

1. 登录平台，进入侧栏 **「MCP 接入」** 页。
2. **生成密钥**（`kbm_` 开头，只显示一次；**轮换后旧密钥立即失效**，每次调用都实时验钥）。
3. **勾选开放的知识库**：Agent 只能检索你勾选的、且你本人有权限的库。
4. **工具开关**（可选）：逐个开/关三个工具；还可以自定义提示词与工具描述。
5. 页面给出连接地址：`http://<服务器IP>:9000/mcp`，配到任意 MCP 客户端：

```json
{
  "mcpServers": {
    "kb": {
      "url": "http://192.168.x.x:9000/mcp",
      "headers": { "Authorization": "Bearer kbm_你的密钥" }
    }
  }
}
```

> 无密钥/错密钥：`tools/list` 返回空清单，一切调用被拒——Agent 什么也看不到，不会泄露库是否存在。

## 4. HTTP 调用详解

### 4.1 第一步：解析范式（拿到 paradigmId）

```bash
curl -s "http://<服务器IP>/api/control-plane/api/v1/proxy/default/serving/api/v1/paradigm/resolve?domain=default&kbIds=kb-xxxx" \
  -H "Authorization: Bearer $TOKEN"
```

响应：

```json
{
  "domain": "default",
  "bound": true,
  "paradigmId": "pd-ab12cd34",
  "name": "官方默认·混合检索",
  "version": 3,
  "url": "/api/v1/paradigm/pd-ab12cd34/search",
  "source": "library"        // library=库级绑定 | official=官方默认
}
```

- `bound: false` = 该域没配置任何范式，找管理员在「范式管理」里绑定默认范式。
- 想看全部可用范式：`GET .../serving/api/v1/paradigm/published`。

### 4.2 第二步：执行检索

```bash
curl -s -X POST "http://<服务器IP>/api/control-plane/api/v1/proxy/default/serving/api/v1/paradigm/pd-ab12cd34/search" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "query": "核心交换机的冗余电源配置要求",
    "domain": "default",
    "kbIds": ["kb-xxxx"],
    "top_k": 10
  }'
```

**请求体参数全表**：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `query` | string | ✅ | 检索词/自然语言问题。空串 → 400 `query_required` |
| `domain` | string | 建议 | 知识域，缺省 `default` |
| `kbIds` | string[] | **强烈建议** | 知识库范围。**不传走域级发布范围，而知识库内容永不进发布——结果必然为空或报 503**。一次可传多个库 |
| `top_k` | int | 可选 | 结果上限 1–200，超范围 → 400 `top_k_invalid` |
| `within` | object | 可选 | 范围硬过滤，只支持 `{"document_refs": ["doc_…"], "section_refs": ["st_…"]}`，其他键 → 400 `unsupported_scope_filter` |
| `filters` | object | 可选 | 类型硬过滤，只支持 `{"asset_types": [...], "evidence_types": [...]}`（取值即返回的 `evidence[].type`，可原样回传筛选） |
| `expansion` | object | 可选 | `{"mode": "auto\|exact\|window\|parent\|whole_document"}`，控制证据片段粒度，默认 auto |
| `debug` | bool | 可选 | true 时响应附 `trace`（算子执行留痕，排查用） |

**成功响应**：

```json
{
  "evidenceResponse": {
    "query": "核心交换机的冗余电源配置要求",
    "evidence": [
      {
        "ref": "ev_8Jq3...",
        "type": "prose",                       // prose|section|table|table_row|list|code|formula|figure_caption|document
        "content": "核心交换机应配置双电源模块，N+1 冗余……",
        "source": {
          "knowledge_base": "网络设备手册",
          "file_name": "核心交换机运维手册.pdf",
          "relative_path": "网络/核心交换机运维手册.pdf",
          "document_ref": "doc_Kx2m...",       // 整篇文档的引用
          "section": "3.2 电源配置",
          "page": 45
        },
        "truncated": false,                    // true = 内容被截断，用 4.3 取全文
        "structure_ref": "st_9Pzq..."          // 结构节点引用（导航/查表格用）
      }
    ],
    "has_more": false
  }
}
```

### 4.3 第三步（可选）：截断证据取全文

`truncated: true` 的证据，用 `ev_` ref 换更大粒度原文：

```bash
curl -s "http://<服务器IP>/api/control-plane/api/v1/proxy/default/serving/api/v1/evidence/ev_8Jq3...?domain=default&kbId=kb-xxxx&mode=parent" \
  -H "Authorization: Bearer $TOKEN"
```

`mode`：`auto`（默认，预算内就大）/ `exact`（原片段）/ `window`（相邻切片）/ `parent`（父章节）/ `whole_document`（整篇）。

## 5. MCP 工具详解

三个工具，职责一句话：**`search_knowledge` 模糊找、`get_knowledge` 深入读、`upload_document` 上传**。

Agent 的典型节奏：先 `get_knowledge`（不带参数）看自己有什么库 → `search_knowledge` 检索 → 拿着返回的 ref 一切深入都走 `get_knowledge`。

通用规则（三个工具都适用）：

- **身份 = 密钥主人**。授权实时判定：开放了但本人权限被收窄的库，调用时自然被拒。
- **范围 = 开放的库**。检索/读取不会越出「MCP 接入」页勾选的库。
- **`domain` 参数可免传**：开放库只覆盖一个域时自动使用（最常见）；跨多域时报错并列出可选域，选一个重试；不要按问题内容猜领域。
- **错误带稳定 code**（如 `unknown_field` / `out_of_scope` / `expired_ref`），按错误提示修参数重试即可。

### 5.1 `search_knowledge` —— 一切检索的起点

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `query` | string | ✅ | 用户原问题，原样传入（不要改写） |
| `domain` | string | 可免传 | 单域自动默认；跨多域报错带清单 |
| `kb_names` | string[] | 可选 | 在开放的多个库中按**库名**缩小范围（大小写不敏感）。不传 = 检索全部开放库。传入的名字必须全部命中开放清单，否则报错并列出当前开放库 |
| `within` | object | 可选 | 范围硬过滤：`{"document_refs": ["doc_…"], "section_refs": ["st_…"]}`，只支持这两个键 |
| `filters` | object | 可选 | 类型硬过滤：`{"asset_types": ["table"], "evidence_types": ["table_row"]}`，类型词用公开词（= `evidence[].type` 取值），只支持这两个键 |
| `expansion` | object | 可选 | `{"mode": "auto\|exact\|window\|parent\|whole_document"}`，证据粒度，默认 auto |
| `top_k` | int | 可选 | 结果上限 1–200 |
| `paradigm` | string | 一般不传 | 范式自动跟随库绑定；显式传错域的范式会报 `paradigm_domain_mismatch` |
| `debug` | bool | 默认 false | true 时响应附 `diagnostics` |

**调用示例**（Agent 视角）：

```
search_knowledge(query="核心交换机的冗余电源配置要求")
search_knowledge(query="电源规格", kb_names=["网络设备手册"], filters={"asset_types": ["table"]}, top_k=5)
```

**返回**：`{query, evidence[], has_more}`，每条 evidence 带 `ref`（`ev_`）/`type`/`content`/`source`（含 `document_ref`、`structure_ref`）/`truncated`。

**典型错误**（结构化对象，不是异常崩溃）：

| error | 含义 | 处置 |
|---|---|---|
| `no_paradigm_configured` | 该域没绑定任何范式（响应附 `available_paradigms` 清单） | 联系管理员绑定 |
| `kb_not_found` | 域下没有可检索内容 | 检查 domain / 确认库已挖掘 |
| `unknown_paradigm` / `paradigm_domain_mismatch` | 显式指定的范式不存在 / 属于别的域 | 按提示改 |
| `HTTP xxx` | 检索服务暂不可用 | 稍后重试 |

### 5.2 `get_knowledge` —— 一切读取行为

一个工具按**入口**自动分流，返回都带 `view` 字段自标识：

| 你给的入口 | 行为 | 返回 `view` |
|---|---|---|
| 什么都不传 | 域→库 顶层浏览 | `kb_tree` |
| 只传 `kb_name` | 该库文件清单（分页） | `documents` |
| `ref=ev_`（可加 `mode`） | 证据原文展开 | `evidence_content` |
| `ref=doc_`（可加 `limit`/`cursor`） | 整篇文档分页读 | `document_content` |
| 只传 `ref=st_` | **能力报告**：可导航关系 / 表格 schema（columns）/ 可过滤聚合字段 + 下一步提示 | `capabilities` |
| `ref=st_` + `query` | 表格精确查询（DSL） | `table_rows` / `aggregate` |
| `ref=st_` + `relation` | 结构关系导航 | `navigation` |

**参数表**：

| 参数 | 适用分支 | 说明 |
|---|---|---|
| `ref` | ref 分支 | `ev_` → 可用 `mode`；`doc_` → 可用 `limit`/`cursor`；`st_` → 可用 `query` 或 `relation` |
| `kb_name` | 浏览 | 列该库文件清单；**不能与 `ref` 同时传** |
| `domain` | 全部 | 路由域；单域可免传 |
| `mode` | 仅 `ev_` | `auto\|exact\|window\|parent\|whole_document`；`truncated=true` 的证据取全用 |
| `relation` | 仅 `st_` | `parent / children / previous / next / ancestors / descendants / container / caption / footnotes / references`（能力报告会列出目标支持哪些） |
| `query` | 仅 `st_`（表格资产） | DSL（见下）；字段名以能力报告 `assets[].columns[].name` 为准——**不是模糊搜索** |
| `depth` | 仅 ancestors/descendants | 层数，默认 1，上限 3 |
| `limit` | 分页类 | `doc_` 每页切片 ≤200 默认 100；navigation ≤200 默认 50；documents ≤200 默认 50 |
| `cursor` | `doc_` 与 navigation | 上一页返回的游标**原样传回** |
| `offset` | 仅 documents 视图 | 分页偏移 |
| `kb_names` | 仅 ref 分支 | 限定库范围（与 search 的 `kb_names` 同义，默认全部开放库） |

**表格查询 DSL 示例**（先拿能力报告看列名，再查）：

```
get_knowledge(ref="st_9Pzq...")                        # 先看能力报告：columns、relations
get_knowledge(ref="st_9Pzq...", query={
    "select": ["额定功率", "冗余配置"],
    "where": [{"field": "额定功率", "op": "lte", "value": 2000}],
    "order_by": [{"field": "额定功率", "direction": "asc"}],
    "limit": 20
})
get_knowledge(ref="st_9Pzq...", query={"aggregate": {"op": "avg", "field": "额定功率"}})
get_knowledge(ref="st_9Pzq...", relation="children")   # 沿结构导航
```

**互斥规则**（传错会得到明确报错，不会静默降级）：`ref` 与 `kb_name` 互斥；`ev_` 只认 `mode`；`doc_` 只认 `limit`/`cursor`；`st_` 上 `query` 与 `relation` 互斥。

### 5.3 `upload_document` —— 上传文件

| 参数 | 说明 |
|---|---|
| `kb_name` | 目标库（顶层浏览返回的 name） |
| `filenames` | 文件名列表（含扩展名，如 `["手册.pdf", "notes.md"]`；单文件也传单元素列表），每个不含路径 |

**两步直传**（大文件不走 base64——会撑爆工具参数）：

```
① upload_document(kb_name="网络手册库", filenames=["手册.pdf", "notes.md"])
   → 返回每个文件的 upload_url（一次性凭证，10 分钟内单次有效，无需认证头）
② curl -X PUT --data-binary @手册.pdf "<该文件的 upload_url>"
   → PUT 的响应即该文件的上传与挖掘入队结果
```

五条注意：

1. **上传自动排队挖掘**——库空闲则立即整库增量挖掘；库正在挖掘/审核中则排队串行执行。挖掘完成后内容才可检索：刚上传的文件 `search_knowledge` 查不到是正常的。
2. 需要对该库有**编辑权限**（owner/editor）。
3. 文件类型与网页上传同源：zip/hdx/chm 归档会**自动解压成多个文档**（与网页端上传 zip 一致，解压出的文档在「压缩包名/」目录下）；大量小文件打包一个 zip 传单个 URL 更高效。
4. 上限：普通文件 50MB；zip/hdx/chm 归档与网页端一致（500MB）。
5. 票据超时或 PUT 失败：重调本工具取新 URL 重传即可（票据单次使用）。

### 5.4 典型工作流（Agent 演示）

```
① 不知道有什么 → get_knowledge()                          # 域→库树
② 检索          → search_knowledge(query="……")
③ 证据被截断    → get_knowledge(ref="ev_…", mode="parent")
④ 要整篇文档    → get_knowledge(ref="doc_…", limit=100)   # 翻页用 cursor
⑤ 碰到表格      → get_knowledge(ref="st_…")               # 先看能力报告
                → get_knowledge(ref="st_…", query={…})    # 精确查表格
⑥ 结构上下游    → get_knowledge(ref="st_…", relation="children")
```

## 6. 错误码对照与排查（HTTP）

所有错误都是**结构化响应**（`{"error": "<code>", "message": "..."}`），不要靠猜 HTTP 状态码。

| HTTP | error code | 含义 | 怎么办 |
|---|---|---|---|
| 400 | `query_required` | 没传检索词 | 补 `query` |
| 400 | `top_k_invalid` / `expansion_invalid` | 参数越界 | 按取值范围改 |
| 400 | `unsupported_scope_filter` | `within`/`filters` 传了不支持的键 | 只用白名单键 |
| 400 | `empty_scope` | 范围内没有可读内容 | 检查 kbIds 是否正确 |
| 401 | `unauthenticated` | 没带 / token 过期 | 重新登录，带 `Authorization: Bearer` |
| 404 | `kb_not_found` | **库不存在或你对它没权限**（两者故意同码，防探测） | 确认 kbId；确认账号是库主/成员或库是 public（见 §7） |
| 404 | `no_active_kb_build` | 目标库没有可检索内容 | 库还没挖完，或全部文档挖掘失败；先完成一次挖掘 |
| 503 | `no_active_release` | 没传 `kbIds` 且域内无激活发布 | **补上 kbIds**（知识库检索必传） |
| 500 | `internal_error` | 服务端异常 | 看 serving 日志 / 联系管理员 |

MCP 侧的错误以 `ToolError` 文本返回（中文、带稳定 code 与修正提示），检索类结构化错误见 §5.1 表。

## 7. 权限说明（重要）

检索能看到的库 = **调用身份**的可见范围，规则：**库主（owner）/ 库成员（member）/ 库是 public**，三选一。

- HTTP：token 是谁的，身份就是谁（网关自动从 JWT 注入身份头）。
- MCP：身份 = 密钥主人，且额外受「开放库勾选」限制（开放 ∩ 有权限）。
- 别人建的**私有库**，即使你是平台管理员，直接检索也会 404 `kb_not_found`——这是 1.0.2 的已知问题（检索侧授权没有管理员旁路，与网页端「管理员可见全部库」不一致）。**规避**：让库主把你加为库成员，或把库设为 public，或用库主身份/密钥。
- 脚本建议专建服务账号，把它加进需要的库里（成员即可，只读用途）。

## 8. 记录与留痕（当前版本行为）

- 每次检索（网页/HTTP/MCP 同等）在 `serving_query_logs` 留一条：**query 原文、域、耗时、范式、结果条数与来源（库/文件）**。
- **不记录发起人工号/账号**——三种调用方式在日志里无法区分谁发的。MCP 密钥只有分钟级「最后使用时间」。
- 如需「谁检索了什么」的审计能力，需后续版本补充。

## 9. 常见坑

1. **HTTP 忘了传 `kbIds`** → 503 `no_active_release` 或空结果。知识库检索永远带上它。
2. **网关路径拼错**：`/api/control-plane/api/v1/proxy/{domain}/serving/...`，`serving` 前缀不能少（它决定路由到检索服务）。
3. **Windows 下 curl 中文乱码/GBK 报错**：请求体写成 UTF-8 的 json 文件，用 `--data-binary @body.json`，不要 `-d '中文'` 内联。
4. **token 12 小时过期**：脚本里捕获 401 自动重登。
5. **检索报 404 但网页就绪度显示「语义可搜」** → 99% 是权限问题（§7），不是数据问题。
6. **内网直连**：serving 端口 `127.0.0.1:8081` 只绑定在部署机本机回环——**其他机器访问必须走 80 端口网关路径**。部署机上的脚本可直连 `http://127.0.0.1:8081/api/v1/paradigm/{id}/search`（身份用 `X-KB-User: <用户名>` 请求头，与 Bearer token 二选一）。
7. **MCP 报「工具未开放」/「知识库未开放」**：到「MCP 接入」页检查工具开关与开放库勾选。
8. **MCP 密钥轮换后 Agent 全部 401**：轮换即旧钥失效（无宽限期），重新生成并更新客户端配置。
