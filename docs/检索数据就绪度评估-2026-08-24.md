## 1. 结论速览

- **文件字节只在 MinIO，PG 不存文件内容**；检索主数据面是 PG 的切片表（结构化可过滤文本）。
- **MinIO 不承担检索**（对象存储无查询能力）；它承担"agentic 深挖的全量结构"与"证据回放的原文"。
- 切片层 v2 已就位：语义角色 / 表格语义类型 / 章节链 / 证据链 / 幂等重切全部落库可用。
- **检索入口层为零**（无任何 search API）；文本索引、GIN、向量层均未建（扩展已装：pgvector + pg_trgm）。

## 2. 结构化数据分布（两层存储）

```
                ┌─ MinIO: agentickb-dev-parse ──────────────────────┐
 解析产出(源) ─→ │ Parse IR JSON（每知识快照一份，内容寻址 v1/{sha}）  │
                │ - 元素图：标题/段落/代码/表格(TableAsset 单元格级)   │
                │ - 关系：parent_of / next_in_reading_order / caption│
                │ - 容器与质量诊断                                    │
                └───────────────┬───────────────────────────────────┘
                                │ 编译（策略可换档；重切不重新解析，A08）
                                ▼
                ┌─ PostgreSQL ──────────────────────────────────────┐
 检索视图(用) ←─ │ asset_raw_segments        切片=可过滤的结构化文本  │
                │ asset_segment_element_links 切片↔IR元素证据链      │
                │ asset_retrieval_units / _embeddings  向量层(空)    │
                └───────────────────────────────────────────────────┘
```

| 存储 | 角色 | 检索中的定位 |
|---|---|---|
| PG `asset_raw_segments` | 切片检索视图 | **主检索面**：结构化过滤 + 文本匹配 |
| MinIO parse 桶 | Parse IR 全量结构 | **agentic 深挖面**：命中后按 element_ids 取整份元素图 |
| MinIO source 桶 | 原始文件字节（内容寻址去重） | **证据回放面**：溯源到原文 |

前端"结构化数据"页签的数据来源为混合：切片/证据链读 PG；大纲/元素明细/表格网格读回 parse 桶 IR。

| 列 | 类型 | 检索用途 |

| segment_index | int | 阅读序 |

## 5. 已备能力清单

1. **结构化过滤轴落库**：block_type × semantic_role × 章节 × 表格类型 × token——SQL 即算子化检索的过滤面。
2. **证据链闭环**：segment → element_ids → IR（MinIO）→ source spans → 原文字节，五级可回溯（agentic 检索的三跳数据契约已通）。
3. **快照版本化 + 幂等重切**：换切片策略产新快照不重新解析（IR 复用）；多版本并存可回溯。
4. **内容寻址去重**：同内容文件/IR 只存一份（sha 寻址）。
5. **向量/模糊扩展就绪**：pgvector + pg_trgm 已装，建列建索引即可用。
6. **检索相关空表已建**：asset_retrieval_units / asset_retrieval_embeddings 的 DDL 与状态机就位。

## 7. 三条检索路线（供评估，不互斥）

**A. 算子化检索（最快，纯 PG）**
切片表建 trgm/tsvector 索引 + structure_json GIN → SQL 检索算子：
`过滤（类型/角色/章节/表格类型）+ 文本匹配（trgm 模糊或 FTS）+ 快照域内排序`。
预估一天量级；直接消费现有 v2 切片。

**B. 向量检索**
asset_retrieval_units + embeddings + pgvector；embedding 算子接进现有"快速向量检索"范式
（范式/参数档位/工作流骨架已就位，只差算子接线与验证）。切片→检索单元的映射可按
block_type/semantic_role 决定嵌入策略（如 table 整片嵌入、code 整片嵌入）。

**C. agentic 检索**
三个工具即可编排：`SQL 筛切片`（A 的能力）/ `取文档 IR 全量结构`（MinIO parse，含单元格级表格）/
`取原文字节`（MinIO source）。数据契约已闭环，纯工具层工作。

建议评估顺序：A 打底 → B 上语义 → C 做编排；A+B 即构成混合检索底座。

## 8. 附：关键机制备忘（评估时需要知道的语义）

- **快照域隔离**：所有资产挂 document_snapshot_id；文档"当前知识"= 最新 READY 快照；换策略产新快照不改旧版。
- **表格双形态**：整片（默认，含 table_kind）与行片（可选视图，自描述"列名=值"）由切片策略决定；单元格级数据永远在 IR（TableAsset）。
- **语义角色是启发式**（章节标题模式推导）：definition/enumeration/example/conclusion/constraint/navigation/overview；准确率未评估，检索侧使用时建议先按"弱信号过滤轴"对待。
- **重切幂等**：compiler_fingerprint 一致则复用；同内容多文档共享快照。
- **多域**：domain 字段贯穿（快照/切片同域落库）；KB 与 domain 的绑定关系见 kb 范式绑定。
