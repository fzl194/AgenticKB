# 语义知识基础设施：阶段进展汇报

> 对照基线：《语义知识基础设施-项目概述》（2026 年 8 月初版）
> 汇报时间：2026-08-19

## 一、本轮工作在整体路线中的位置

项目概述确立的技术路线，是把资料预先编译为多形态、可追溯的知识资产，再由可编排的检索范式按任务交付给人和 Agent。对照这条路线，系统此前已具备知识库管理、库内加工闭环、版本化工作流和检索侧的算子底座；本轮工作集中补齐了链路最上游的一段——知识生产的地基。

这样安排的原因很直接：整条链路的效果上限由语料加工阶段决定。专业资料的信息密度藏在结构里，多级章节、跨页表格、合并单元格、图表与图题的对应关系，如果在解析入库时就被压平丢弃，后续再强的检索与推理都无法找回。概述中把"补齐挖掘侧算子化"列为下一阶段重点，本轮正是对这一重点的落地：围绕"解析保真、质量受控、按场景编译"三个环节，完成了从能力建设到真实环境验证的完整闭环。

用一个对照来概括变化：此前一份文档入库，产出的是一组文本片段，加工质量靠人工抽查；现在入库产出的是带标题层级、表格网格和原文定位的结构化知识，每次加工自动评分、合格才形成正式版本，切片方式可以按场景调整，用户在前端能直接查看解析结果。知识生产从工程上的黑盒过程，变成了可度量、可追溯、可检查的过程。

## 二、解析保真：让机器读懂专业资料的原始结构

本轮为七种常用格式（Word、Excel、PPT、HTML、PDF、Markdown、TXT）重建了结构化解析能力。之所以称为重建，是因为旧链路对不同格式做了大量统一化预处理，结构信息在进入切片之前就已经丢失；新链路按格式原生解析，标题树、表格网格、合并单元格、图文对应关系直接进入统一的知识表示，每个段落和单元格都保留指向原文位置的定位信息。

这项能力的验收没有停留在自造样例。项目以一份 73 页的真实中文专业论文为基准，对同一内容的 Word 版和 PDF 版分别解析后逐项对照：标题层级对齐率超过 98%，正文内容覆盖和证据定位接近满分，阅读顺序完全正确。在此基础上沉淀了 50 份覆盖七种格式、四种难度类型（正例、复杂结构、反例、退化输入）的标准语料，作为长期回归基准——解析质量从"看起来还行"变成了六项指标可持续度量、每次变更自动守护的状态。这也正是概述第六章三层评价体系中 L1 层（知识构建层）的落地：先能回答"关键资料是否被正确加工"，再谈检索与回答质量。

具体到"抽取了哪些结构化信息"，当前一份文档入库后，系统得到四个层面的结构化结果。一是文档骨架：多级标题树（章节父子关系）、正确的阅读顺序（含双栏排版的栏序）、各格式的原生容器（PDF 的页、Excel 的工作簿与工作表、PPT 的幻灯片），以及跨页段落和跨页表格的续接关系。二是内容元素：标题、段落、带层级的列表项、表格、图片、代码与引用块，以及图题表题与所属图表的自动绑定。三是表格细节：行列网格与单元格文本、合并单元格（跨行跨列）、表头区域识别，Excel 的公式与显示值分离保留、隐藏行列标记。四是证据定位：每个段落和单元格都指向原文的具体位置——PDF 到页与页面区域，Excel 到工作表与单元格地址，Word 到文档内部结构位置，HTML 到页面节点路径，普通文本到行号，检索结果因此可以回跳原文。图片当前保留资产记录与图题绑定，图片内容的语义识别预留了接口，接入模型即可启用；页眉页脚、脚注、批注等不进入知识内容，但其存在被如实记录，不做静默丢弃。

## 三、质量受控：知识入库从加工完成变成加工可信

知识库最大的隐性成本不是检索不准，而是"库里有多少是对的"。解析失败被静默跳过、新旧版本混淆、加工方法无从追溯，这些问题在演示里看不见，在业务使用中迟早暴露。本轮为此建立了一套完整的质量管控机制，可以概括为五条保证。

第一，合格才入库：每次加工自动评分，覆盖内容完整率、结构准确率、表格完整率、证据可定位率和阅读顺序，不达标的结果被直接拒绝，知识库不接收垃圾数据。第二，入库有出生证明：每个知识版本记录它来自哪份文件的第几个版本、用什么方法加工、质量结论如何，任何一条知识都能回答"凭什么相信它"。第三，版本不张冠李戴：加工期间资料被更新的，过期输入的结果自动作废，不会拿旧内容冒充新知识。第四，失败看得见且有兜底：解析故障自动切换备用方案并保留全程审计记录，失败原因可查。第五，方法升级不重复花钱：加工的中间结果已存档，解析方法改进后直接复用重算，不需要重新解析原始文件——这为将来接入按量计费的云端解析服务预置了成本控制手段。

这套机制使知识库从"一堆加工结果"变成"可审计的知识资产账本"，也使概述中"快照、构建和发布控制生效范围"的规划有了可靠的前提。

## 四、按场景编译：同一份资料产出不同形状的知识

概述第四章提出，同一份资料应能按场景编译成多种知识形态。本轮在切片环节把这个方向变成了现实能力。

新链路的切片按文档结构编译而非按字数机械切分：段落自动携带所属的章节路径，检索命中时能看到内容在文档中的位置；表格编译为整表加逐数据行，每一行自带表头和表名，表格类问答召回的结果天然带列语义；页眉页脚等与知识无关的内容不再混入。切片的粒度、合并策略、表格视图、上下文注入都是可配置的档位，同一份资料可以按检索场景的不同编译出多种知识视图；调整策略时复用已解析的结果重新切片，不产生重复的解析成本。

与现有系统的衔接采取了两条原则。对下游，新切片以兼容格式写入现有资产表，增强、向量化、检索等既有环节不需要任何改动即可消费；对用户，知识库的文档页面新增了结构化数据视图，直接展示每份文件解析出的标题树、表格、切片清单和质量结论——知识生产第一次对使用者变得透明，也为后续的人工复核和纠错开了入口。当前新旧两条加工链路并行运行、互不干扰，正式切换按计划在工作流层平稳完成。

## 五、工程质量与验证

本轮全部能力按照测试先行的方式开发，累计 715 项自动化测试；每个阶段都在真实环境（对象存储加生产数据库）端到端验证后交付，而非仅本地模拟。此外引入了对抗评审机制：由多个独立评审线对新代码做攻击性审查，仅一轮即发现并修复了 16 项常规测试难以覆盖的深层缺陷，包括跨文档知识共享、异常恢复等场景。该机制已固化为每个阶段的例行环节。全部技术决策均有留档，可追溯。

需要说明的是，与项目概述的口径一致，当前阶段的验证重点是链路正确性与可追溯性；演示语料的处理规模和指标不作为真实业务成果引用。

## 六、下一步

近期工作是完成生产链路的正式切换：解析与切片作为标准能力接入挖掘范式编排，"更新知识"任务走新链路，范式构建器对新能力呈现为默认零配置、可精调的参数档位，新链知识进入在线检索发布。这与概述下一阶段第 1、2 项直接衔接。

中期按概述第四章的知识形态矩阵逐步扩展：依托本轮的解析与切片底座，优先建设层级树与目录导航（结构信息已具备），推进表格深度问答、图文理解（云端模型接口已预留，配置即接入），并随着实体链路完善推进图谱类资产。相应的研究依据已按证据分级整理在 agent_knowledge_research 工作区，覆盖知识编译、知识图谱、程序性知识、主动检索和持续记忆五条路线。

远期方向是面向 Agent 的主动知识工程：知识不仅能被检索，还能被 Agent 在任务过程中主动获取、校验和持续积累，形成任务驱动的知识编译闭环。本轮建成的结构化解析、质量门控和可重编译切片，正是这条路线所依赖的地基。
